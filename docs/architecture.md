# 프로젝트 구조

이 문서는 현재 확정된 저장소 운영과 시스템 구조를 설명한다. 기술이나 연결 방식을 가정해 채우지 않는다.

## 확정

- 저장소 구성: 모노레포
- 개발 도구: Codex
- 필요한 구성요소: Figma 플러그인, 웹사이트, 백엔드 서버
- 공통 에이전트 지침: 루트 `AGENTS.md`
- 현재 제품·구조·절차 문서: `docs/`
- 개별 작업 기록: `docs/changes/`에서 작업별로 관리하고 필요한 경우에만 읽음

## 허용된 폴더 구조

현재 승인된 고정 구조는 다음과 같다. `.git`은 Git 관리 메타데이터이며 프로젝트 산출물 폴더가 아니다.

```text
cheddar/
├── AGENTS.md
├── README.md
├── .github/
│   └── pull_request_template.md
└── docs/
    ├── product.md
    ├── architecture.md
    ├── workflow.md
    ├── decisions/
    │   └── README.md
    ├── changes/
    │   └── README.md
    └── templates/
        └── change.md
```

- 고정 폴더: `.github/`, `docs/`, `docs/decisions/`, `docs/changes/`, `docs/templates/`.
- 이미 합의된 작업 기록 형식으로 `docs/changes/<change-id>/` 한 단계의 폴더를 허용한다. 현재 사용자가 요청한 작업에 기록이 필요한 경우에만 생성한다. 그 아래의 추가 폴더는 별도 승인이 필요하다.
- 결정 기록은 `docs/decisions/` 안에 Markdown 파일로 추가한다. 작업·결정 기록 생성에 관한 상세 기준은 각 디렉터리의 안내를 따른다.
- 기능별 소스 폴더, `.agents/`, `.codex/`, 워크플로 폴더 등 이 목록 밖의 폴더는 아직 승인되지 않았다. 향후 확장 예시나 미정 항목에 언급된 이름을 생성 허가로 해석하지 않는다.
- 폴더 생성·이동·이름 변경으로 이 범위를 벗어나려면 경로·목적·영향을 먼저 제시하고 명시적 승인을 받는다. 승인 후 실제 구조와 이 목록을 함께 갱신한다. 에이전트가 목록을 먼저 수정해 스스로 승인할 수 없다.
- 기존에 발견한 폴더는 그 존재만으로 승인된 구조에 편입하지 않는다. 목록과 다르면 사용자 변경 여부와 필요성을 확인하고 임의 삭제하지 않는다.

## 임시 파일과 도구 산출물

임시 스크립트·조사 자료·다운로드·로그·스크린샷·캐시는 저장소 및 worktree 밖의 OS 임시 경로를 사용한다. `tmp/`, `work/`, 숨김 폴더를 만들거나 `.gitignore`에 등록해 저장소 안에 두지 않는다. 영속 산출물로 보관해야 할 경우에는 목적과 저장 경로를 사용자와 합의한다.

빌드·의존성·테스트 도구의 저장소 내부 산출물 경로는 아직 미정이며 승인된 예외가 없다. 도구를 도입할 때 필요한 경로와 관리 방법을 함께 결정한다. 승인된 예외가 생겨도 다른 임시 파일의 저장 허가로 확대하지 않는다.

## 갱신 기준

구조가 결정되면 이 문서에 현재 상태를 반영한다. 여러 대안 중 선택한 이유가 이후 판단에 필요하면 `decisions/`에 별도 기록을 남기고 연결한다. 과거 작업 계획만으로 현재 구조를 판단하지 않는다.
