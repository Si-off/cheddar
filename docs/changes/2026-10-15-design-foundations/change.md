# 작업: 디자인 토큰과 스탠드얼론 미리보기

- 상태: 완료, 사용자 시각 검토 대기
- 요청 근거: 라이트 모드 톤앤매너와 원칙에 맞는 구체적인 토큰을 작업하고, 확인 가능한 스탠드얼론 HTML을 만들어 달라는 요청.
- 기준: main, 20136d3. 이전 DESIGN.md 커밋은 원격 푸시 자동 승인 거절로 로컬에만 존재한다.
- 실행 범위: 토큰 구현안과 로컬 미리보기, 관련 문서 및 검증. 원격 푸시는 이전 승인 검토에서 보류된 상태를 유지한다.
- 마지막 확인: 2026-10-15

## 계획

1. 기존 primary, 폰트, 타이포그래피와 간격 기본값을 유지하고 팔레트, 의미별 상태, 크기, 그림자, 모션을 구체화한다.
2. packages/design-tokens/src/theme.css를 원본으로 삼아 docs/design-foundations.html에 CSS와 폰트를 내장한다. 재생성 도구와 템플릿은 기존 packages/design-tokens/에 둔다.
3. 미리보기에서 색상, 글자, 간격, 형태, 동작을 확인하고 인터랙션 및 키보드, 좁은 화면을 검증한다.
4. 기본 검사와 독립 UX 문구 검수를 수행한다.

## 완료 조건

- HTML 파일 하나를 열면 네트워크 없이 폰트, 스타일, 동작을 확인할 수 있다.
- 미리보기의 토큰 값은 공통 CSS와 일치한다.
- 기본 primary와 폰트는 유지하며, 세부 토큰은 사용자 검토를 위한 구현안으로 제시한다.
- DESIGN.md의 방향과 사용자의 정보 절제 원칙을 따른다.

## 진행과 인계

- 공통 CSS 토큰과 재생성 가능한 스탠드얼론 HTML 구현 완료.
- 구체적인 값에 대한 최종 시각 검토는 사용자가 미리보기를 확인한 뒤 진행한다.

## 검증 결과

- `pnpm check` 통과: lint, 웹·플러그인 타입 검사, 양쪽 빌드 완료. 폰트 내장 HTML이 기본 1MiB 검사 한도를 넘는 경고 1건이 있어 `pnpm exec biome check --files-max-size=7000000 docs/design-foundations.html`로 생성 파일도 별도 검사했고 통과했다.
- primary 위 흰색 텍스트 대비 6.96:1. 보조 텍스트와 상태 텍스트 7개 조합은 4.5:1 이상, 컨트롤 경계는 표면과 3:1 이상 확인.
- 브라우저에서 색상 선택, 샘플 문장 변경, 여백 조절, 모션 재생·감소, Enter 조작, 2px 키보드 포커스, 다이얼로그 열기·Escape 닫기, 입력 초기화 및 CSS 다운로드 확인. 브라우저 오류 로그 없음.
- 390px 화면에서 6개 분류의 페이지 가로 넘침 없음. 메뉴 자체는 가로 스크롤로 접근.
- HTML의 외부 스타일·스크립트·폰트 요청이 없음을 정적 검사. 공통 CSS와 내장 CSS, 다운로드 CSS 일치 및 재생성 결과 동일 확인.
- 브라우저 도구는 file 프로토콜을 허용하지 않아 파일 직접 열기 실행 검증은 수행하지 못했다. 로컬 HTTP에서 렌더링과 동작을 확인했다.
- 독립 `ux-writing-review` 에이전트(gpt-6-luna, high)가 신규 템플릿 전체의 문구·표시 조건·접근성 이름을 코드 기반으로 검수: 문제 없음. 해당 에이전트는 실행 화면을 검수하지 않았으며 화면 검증은 메인 에이전트가 수행했다.
- 새로운 폴더는 허용된 작업 기록 폴더만 사용. 빌드 산출물은 기존 승인 경로에 생성했고 임시 파일은 저장소에 추가하지 않았다.

## 반영 범위

- DESIGN.md와 README에 미리보기를 연결하고 구조 문서의 현재 토큰 구현 상태를 갱신했다.
- 앱 화면이나 공통 UI 컴포넌트의 구조·문구는 변경하지 않았다. 기존 토큰의 의미별 색상이 새 팔레트를 참조하므로 이를 사용하는 앱의 색상도 변경된다. 기존 컴포넌트의 모든 치수·전환을 새 토큰으로 이관하는 작업은 포함하지 않았다.
- 로컬 결과이며 원격 푸시, PR, 배포는 수행하지 않았다. 이전 기본 브랜치 푸시의 자동 승인 거절 이후 추가 푸시 승인은 받지 않았다.

## 후속: 문구 생성 기준과 선택 컨트롤 모션

- 사용자 요청: 합의한 문구 생성 기준을 `docs/ux-writing.md`와 검수 스킬에 서브에이전트가 반영하고, 메인은 체크박스·라디오·스위치 애니메이션을 구현. 기존 미리보기 문구는 유지. 최적화를 고려하며 Motion 사용은 선택 사항.
- 문서 담당 서브에이전트가 위 두 파일만 수정했다. 생성 필요성과 현재 표시 위치를 별도로 판단하고, 삭제 시 생기는 구체적인 어려움을 검수 근거로 요구하도록 반영했다. 미리보기와 데모에도 동일 적용한다.
- 메인은 네이티브 입력 요소와 접근성 이름을 유지하면서 장식 레이어에 체크 표시·선택점의 opacity/scale 전환을 적용했다. 스위치는 트랙 opacity와 손잡이 transform을 전환한다. 상태 전환은 기존 180ms 토큰을 사용하고, 모션 감소 시 0ms가 된다.
- 추가 의존성, JavaScript 이벤트·반복 루프, 지속적인 will-change 없이 CSS transition으로 구현했다. 입력을 빠르게 바꾸면 현재 상태에서 새 목표로 전환한다. 강제 색상 모드에서는 네이티브 체크박스·라디오를 표시하도록 폴백을 두었다.
- 표시 문구, 컨트롤 이름, 초기 상태 및 미리보기 JavaScript가 기준 커밋과 동일함을 검사했다. 문구나 문구 의미의 표시 조건은 변경하지 않아 이번 UI 변경에는 추가 UX 문구 검수를 요구하지 않는다.
- 브라우저 검증: 체크박스 Space, 라디오 방향키, 스위치 Space, 2px 포커스, 스위치 6회 연속 클릭 후 최종 상태 확인. 전환 속성 opacity/transform과 180ms, 모션 감소 후 세 컨트롤 모두 0ms 확인. 강제 색상 모드 실제 실행과 프레임 단위 성능 프로파일링은 수행하지 않았다.
- `pnpm check` 통과. 폰트 내장 HTML은 기본 검사 크기 한도 경고가 있어 `biome check --files-max-size=7000000`으로 원본·생성 HTML을 별도 검사했고 통과했다. `git diff --check` 통과.
- 스킬 frontmatter가 기존과 동일함을 확인했다. skill-creator의 quick_validate.py는 시스템·번들 Python 모두 PyYAML이 없어 실행하지 못했다.
- 원격 푸시·PR·배포는 수행하지 않았다.

## 후속: 버튼 색상 반응과 secondary

- 사용자 결정: 버튼 클릭 시 위치 이동 없이 색상만 변화, 모션 감소 기능 미도입, secondary 추가, 체크박스 상태 전환 및 라디오 내부 원 확대.
- 버튼의 누름 이동과 색상 스와치 호버 이동, 선택 컨트롤 본체의 누름 축소를 제거했다. 스위치 손잡이 이동은 상태 표현으로 유지했다.
- secondary 구현안은 `#2F746F`이며 hover, active, subtle, foreground 토큰과 미리보기 스와치·보조 버튼에 적용했다. 일반 텍스트 대비는 기본 5.46:1, 호버 7.32:1, 누름 9.47:1.
- 체크박스는 배경과 체크 표시의 opacity를 240ms로 양방향 전환한다. 라디오 내부 원은 8px에서 10px로 확대했다. 반복 JavaScript나 라이브러리는 추가하지 않았다.
- 공통 CSS·내장 미리보기·다운로드 CSS의 모션 감소 분기와 미리보기 설정·안내를 제거했다. 웹·플러그인 MotionConfig는 reducedMotion="never"로 변경했다. 이전 모션 감소 관련 결정과 검증 기록은 과거 이력이며 현재 기준은 이 절과 DESIGN.md다.
- 브라우저에서 체크박스 Space 선택·해제 중 opacity 중간값, 라디오 방향키 및 10px 내부 원, 모션 감소 스위치 제거, 모션 재생, secondary 선택·대비 값, 390px 화면의 넘침 없음을 확인했다.
- `pnpm check` 및 생성 HTML의 크기 한도를 늘린 별도 Biome 검사 통과. `git diff --check` 통과.
- 독립 UX 문구 검수: 기준 6d4e22a, 신규 secondary 명칭·값 및 모션 감소 UI 삭제 범위에서 문제 없음. 기존 불필요 문구를 따로 정리하지 말라는 사용자 지시는 유지했다.
- DESIGN.md와 README의 현재 기준을 갱신했다. 원격 푸시·PR·배포는 수행하지 않았다.

## 후속: 내부 변화 중심의 모션 방향

- 사용자 의도: 요소 전체의 크기·위치 변화 대신 내부 채움, 색상 전환, SVG 선 그리기를 사용한다. 스위치는 고정된 트랙 안에서 손잡이가 움직이며 배경색이 전환된다. 스탠드얼론은 프로젝트의 디자인 방향을 검토하는 시각 실험이다.
- DESIGN.md에 이를 일반적인 모션 원칙으로 반영하고 README와 함께 미리보기의 목적을 명확히 했다. 이번 변경은 제품 컴포넌트 구현이나 API·동작 명세를 확정하지 않는다.
- 체크박스는 clip-path로 배경이 차오르고 stroke-dashoffset으로 체크 선이 그려지거나 지워진다. 라디오 내부 원의 scale을 제거하고 고정된 10px 크기에서 opacity만 전환한다. 스위치 손잡이 이동과 배경 전환은 유지했다.
- 모션 샘플의 카드 이동을 제거하고 내부 채움과 선 그리기를 재생하도록 변경했다. 다이얼로그 등장도 이동 없이 opacity만 전환한다. 재생은 브라우저 기본 Web Animations API를 사용하며 기존 재생을 취소하고 다시 시작한다. 강제 레이아웃 읽기, 반복 타이머, 추가 라이브러리는 사용하지 않는다.
- 기준 HEAD와 HTML의 표시 문구가 동일함을 검사했다. 추가된 시각 샘플은 aria-hidden으로 처리했고 기존 접근성 이름과 표시 조건은 유지했다. 새 문구 변경이 없어 별도 UX 문구 검수 대상은 없다.
- 브라우저에서 체크박스 선택·해제의 clip-path와 선 길이 중간값 및 완료값, 라디오 방향키 전환과 transform 없음, 스위치 키보드 전환을 확인했다. 모션 재생 전후 카드 좌표와 크기가 동일하며 재생 중 내부 clip-path와 stroke-dashoffset만 변함을 확인했다.
- 390px 화면에서 가로 넘침 없음, 브라우저 오류 로그 없음. 프레임 단위 성능 프로파일링은 수행하지 않았다.
- pnpm check 통과. 원본 및 생성 HTML은 크기 한도를 늘린 Biome 검사도 통과했다. git diff --check 통과.
- 원격 푸시·PR·배포는 수행하지 않았다.
