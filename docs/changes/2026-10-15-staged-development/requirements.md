# 대화 합의 인계

2026-10-15 조율 채팅에서 사용자가 선택한 요구를 이후 작업 채팅에 전달한다. 이 문서는 제품의 현재 구현 상태나 모든 단계의 실행 승인을 뜻하지 않는다. 현재 문서와 차이가 있는 항목은 해당 단계 시작 시 대조하고, 확정 요구를 현재 제품·구조 문서에 반영한다. 보호되는 폴더 정책·지침 변경은 별도 승인 절차를 따른다.

## 제품 흐름

- 사람이 수행할 QA 시나리오를 단위테스트 또는 통합테스트로 생성한다.
- 플러그인: 프로젝트 선택 → Figma 선택 프레임 목록 확인 → 업로드.
- 선택 프레임의 데이터·이미지는 하나의 업로드 묶음이 되어 해당 프로젝트의 웹에 나타난다. 묶음을 클릭하면 시나리오 작업을 시작한다.
- 최종 단순화 결정에 따라 플러그인의 업로드 덮어쓰기·버전 관리는 초기 범위에서 제외한다. 앞서 논의한 업로드 교체·이전 원본 정책은 이번 기능으로 구현하지 않는다.
- 첫 범위: 업로드, AI 생성, 사람의 편집·저장, XLSX. 공유 링크와 배포는 후속이다.
- 초기 검증은 로그인 없는 로컬 웹·백엔드·DB 환경이다.

## 프로젝트와 시트

- 프로젝트에서 기본 시트 양식과 화면 ID를 포함한 IA를 관리한다.
- 새 시트에 프로젝트 기본 양식을 복사하고 개별 편집한다. 기본 양식 변경은 기존 시트를 일괄 변경하지 않는다.
- 시트는 AI 생성 전부터 열과 케이스를 편집할 수 있다.
- 기본 케이스 내용: ID·제목·사전조건·수행 단계·기대 결과·우선순위·관련 프레임. IA 화면 ID 연결을 지원한다.
- 사용자 정의 열은 텍스트부터 지원한다. 열 추가·이름·순서·너비 조절, 문자열 검색, 셀 편집, 행 추가·삭제, 여러 셀 복사·붙여넣기, 키보드 이동, 긴 내용 상세 패널을 제공한다.
- 자동 저장하며 저장 상태·실패를 표시하고 실패 시 입력을 보존한다.
- 케이스와 사용자 정의 값의 저장 모델은 표 라이브러리, 열 위치·너비 등 표시 상태와 분리한다.
- XLSX는 현재 시트에 포함된 전체 케이스를 사용자가 지정한 열 이름·순서로 내보낸다. 검색 중에도 시트 전체를 내보내며 후보는 제외한다.

## IA

- 화면 ID는 IA에 포함된 업무 식별자다. Figma node ID와 별개의 의미를 갖는다.
- 수작업 등록·편집 및 XLSX·CSV의 AI 분석을 지원한다.
- 파일 분석 결과는 사용자가 검토·수정·확정한 뒤 등록한다.
- AI가 케이스의 화면 ID 연결을 확신하지 못하면 비워둔다. 그 이유만으로 케이스를 후보에 보내지는 않는다.

## 플로우차트

- 프로젝트 공용이 아니라 시트별로 보관한다.
- 시작·종료·화면·사용자 행동·조건 분기, 방향과 조건이 있는 연결선을 다룬다.
- 웹에서 생성·편집한다. 외부 플로우차트 이미지나 Figma에서 업로드한 플로우차트 프레임도 입력할 수 있다.
- 이미지를 AI가 요소·연결·조건으로 구조화하고 사용자가 확인·수정한다.
- 의미 데이터·화면 ID 연결과 좌표·확대율 같은 표시 상태를 분리한다. AI에 유의미한 구조를 제공한다.
- 통합테스트는 플로우차트 없이도 생성할 수 있다.

## AI

- 실행마다 Claude/OpenAI를 선택한다. API 키·모델 설정은 백엔드 환경변수에서 관리한다.
- 프레임, IA, 선택 입력 설명, 있는 경우 플로우차트, 시트 양식, 기존 케이스 예시를 입력으로 사용한다.
- 사용자가 목표 케이스 수를 지정하지 않는다.
- 생성 방식은 새 시트 생성 / 기존 시트 교체만 지원한다. 앞선 '기존 시트에 추가' 선택은 최종 결정에서 제외됐다.
- 근거가 명확한 케이스는 시트에 포함하고, 추론·모호한 케이스는 이유와 함께 후보로 제시한다.
- 후보의 검토 대기·추가됨·제외됨을 저장한다. 후보 편집·추가·제외와 제외 항목 다시 보기를 지원한다.
- 생성 중 대상 시트를 잠그며 다른 시트는 사용할 수 있다. 교체는 정상 결과 준비 후 수행하고 실패 시 기존 내용을 유지한다.
- LangGraph 사용만 확정했다. 사용자는 '구체적 구현은 구현할 때 논의하겠습니다'라고 명시했다. 노드 구성, 분할 생성, 재시도·복구·검증 상세는 해당 단계에서 사용자와 논의한다.

## 기술·검증·이전

- 기존 React·TypeScript·Vite·FSD·공통 토큰을 유지한다.
- 백엔드는 NestJS + Drizzle + PostgreSQL, 표는 TanStack Table, 플로우차트는 React Flow.
- TanStack Table의 다중 셀 복붙·키보드 편집은 별도 구현·검증 대상이다.
- API·DB·화면 도구의 타입과 책임을 분리하고 기존 OpenAPI SDK 생성 경로를 활용한다.
- 추후 Supabase DB·Render 등의 인프라 사용 가능성을 고려한다. 실제 클라우드 도입·배포는 아직 결정하지 않았다.
- 파일의 실제 위치는 서버 설정으로 관리하고 DB에는 식별자·저장 키를 보관한다. 특정 PC 절대 경로에 데이터 모델을 결합하지 않는다.
- 로컬 영속 파일 저장 경로는 아직 확정하지 않았다.
- 초기 성능 검증 기준은 업로드 묶음 약 20프레임, 시트 약 500케이스다. 이는 생성 개수 목표나 검증된 성능 결과가 아니다.
- 실제 Figma·브라우저 흐름, 데이터 보존·실패 처리, 잘못된 AI 응답, 한글 입력·복붙·접근성, XLSX 내용 일치를 검증한다.
- UI 문구 변경 시 프로젝트가 지정한 독립 UX 문구 검수를 수행한다.
