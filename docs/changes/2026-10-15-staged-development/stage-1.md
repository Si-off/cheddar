# 1단계 작업 지시서 — 기반·공통 계약

## 착수 방식

사용자가 이 작업 채팅에서 시작을 지시한다. 채팅 생성 직후에는 프로젝트 지침과 이 인계 내용, 현재 코드·브랜치를 읽고 준비 상태를 보고한다. 준비용 작업 브랜치 구성 외에 구현·설치·DB 변경·추가 폴더 생성·유료 AI 호출을 자동 시작하지 않는다.

이 작업은 1단계만 담당한다. 조율 채팅은 `01a13d09-b1e9-7b31-ac07-0e6f6b3ab6f6`이다. 사용자 지시 없는 상호 메시지 전송은 하지 않으며, 조율 채팅은 읽기 도구로 상태를 확인할 수 있다.

## 선행 확인

- 루트 및 담당 경로의 AGENTS와 작업별 현재 문서를 읽는다.
- [requirements.md](requirements.md)의 대화 합의와 현재 product·architecture 문서의 차이를 확인한다.
- 원래 main에서 별도 디자인 작업이 진행 중이었다. 자신의 기준 커밋·원격 상태를 확인하고, 다른 작업을 덮어쓰거나 무관한 커밋을 푸시하지 않는다.
- 로컬 PostgreSQL 17 서버 응답은 이전 조사에서 확인했으나 Cheddar DB·role·TCP 접속·권한은 검증하지 않았다. 현재 상태를 다시 확인하고 기존 DB를 초기화하지 않는다.

## 사용자 시작 후 진행할 범위

1. 프로젝트, IA 항목·화면 ID, 업로드 묶음·프레임·파일, 시트 양식·열, 케이스·후보, 시트별 플로우차트, AI 작업 상태의 책임과 참조 관계를 정리한다.
2. NestJS + Drizzle + PostgreSQL 기반과 환경 설정, 마이그레이션·검증 방식을 구체화한다.
3. 필요한 백엔드 내부 경로·테스트·산출물 경로의 정확한 목록·목적·영향을 먼저 제시하고, 기존 허용 구조를 벗어나면 사용자 승인을 받는다.
4. 승인된 범위의 서버 실행·DB 연결·기본 프로젝트 저장·환경 설정·OpenAPI 생성 및 대표 API를 구현·검증한다.
5. 후속 병렬 작업이 공유할 API·타입·오류·저장 계약과 예시를 정리한다. 모든 기능의 백엔드를 미리 구현하지 않는다.
6. 후속 2A·2B·2C의 정확한 담당 파일·공통 파일 소유자·계약 커밋·완료 기준을 제시한다.

## 경계

- 이 단계는 플러그인 업로드·표 UI·IA AI 분석·플로우 편집기·AI 생성 전체 구현을 포함하지 않는다.
- LangGraph 상세 워크플로는 나중에 사용자와 논의한다. 이 단계에서 그래프·재시도·체크포인트 상세를 임의 확정하지 않는다.
- API 키·DB 비밀번호는 채팅이나 로그에 노출하지 않는다. 클라이언트 번들에 넣지 않는다.
- 변경된 현재 동작·구조는 관련 현재 문서에 반영하되, 허용 폴더 정책이나 에이전트 지침을 임의 변경하지 않는다.
- worktree마다 DB·포트·영속 저장 경로 충돌 가능성을 고려한다. 다른 작업의 데이터를 초기화하지 않는다.
