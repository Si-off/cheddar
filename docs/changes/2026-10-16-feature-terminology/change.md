# 작업: 프로젝트 전체 기능 명칭 정리

- 상태: 구현 완료 (기존 시안 포커스 문제와 실행 환경 전환 조건은 아래 기록)
- 근거: 사용자가 이 채팅에서 전체 구현 계획을 승인했다. 프로젝트 → 테스트 시나리오 → 테스트 케이스, 분석 결과 편집으로 확정했다.
- 범위: 웹·플러그인·디자인 시안·현재 문서·코드·API·DB. 로컬 데이터 초기화와 API 일괄 전환 승인. 권한 구현·PR·병합·배포 제외.
- 구조 승인: `apps/api/src/sheets/` → `apps/api/src/test-scenarios/`, 구조 문서의 해당 허용 경로 갱신.
- 기준: `codex/workspace-redesign`, `fc7febc`. 시작 시 시안과 관련 설정·구조 문서·lockfile 변경이 있었으며 보존한다.

## 구현과 판단

- 익숙한 업무 용어 IA·프레임·요구사항·정책·기본 양식은 유지한다. 테스트 범위는 단위/통합 테스트로 통일한다.
- 분석 결과는 생성의 입력이 되는 화면·상태·관계·요구사항·정책 답변이다. 분석 결과 편집으로 기존 케이스가 자동 변경되지는 않는다.
- 혼합 생성 결과의 API 컨테이너를 results/GenerationResultItemDto로 변경한다. AI 출력의 cases/candidates 구분은 보존한다.
- 기존 마이그레이션은 보존한다. 새 마이그레이션은 FK와 고유 제약의 의존 관계를 깨지 않도록 객체를 제자리에서 rename한다.
- 초기화는 별도 로컬 전용 스크립트에서 명시 실행한다. migration이나 서버 시작에서 데이터를 지우지 않는다. 저장 파일 바이트는 삭제하지 않는다.
- UI 수정 전에 imagegen 내장 도구로 명칭 레퍼런스를 생성해 표시했다. 미리보기 전용이며 이미지의 부가 레이아웃·모킹 데이터는 구현 범위가 아니다.

## 검증과 인계

- API/DB, SDK 계약, 웹·플러그인 동작, 디자인 시안, 타입·빌드 및 독립 UX 검수를 수행한다.
- 실제 AI 서비스 호출은 제외한다.
- 최종 결과와 잔여 사항은 아래 완료 결과에 기록한다.

## 완료 결과

- 웹 경로·API·DTO·OpenAPI operation ID·양쪽 SDK·Query·DB·브라우저 초안 저장소의 명칭을 함께 변경했다. SDK는 `apps/api/openapi.json`에서 재생성했다. 이전 API 경로는 제공하지 않는다.
- 사용자가 정한 이름·열 제목, Figma 원문, Excel worksheet와 과거 완료 기록은 보존했다. 공통 UI 미리보기와 토큰 미리보기도 검색했으며 이번 대상 기능 명칭은 없었다.
- 실제 웹의 펼침 보기는 상세 목록으로 변경했다. 시안의 QA 진행은 결과·메모 입력 동작을 유지한다. 분석 결과 편집은 기존 테스트 케이스를 자동 수정하지 않는다.
- 승인된 API 폴더를 `apps/api/src/test-scenarios/`로 변경하고 `docs/architecture.md`의 허용 경로를 갱신했다. 권한 기능은 추가하지 않았다.

### 검증

- `pnpm check` 통과: 전체 Biome 검사·타입 검사·API/웹/플러그인 빌드. 기존 경고 2개(HTML 미리보기 파일 크기, 기존 optional chain 제안)와 정보 2개는 남는다.
- API 동작·계약 테스트 58/58, 플러그인 Node 동작 테스트 13/13 통과. `openapi:check` 통과. AI는 모의 제공자 계약으로 검증했으며 실제 유료 호출은 하지 않았다.
- 실제 제품 브라우저 테스트 38/38 통과: 편집기·분석 결과·생성 결과 24개, 실제 API를 쓰는 프로젝트/IA/기본 양식 13개, 플러그인 UI 1개. 선택자 변경과 환경을 정정한 재검증 결과를 포함한다. 프로젝트/시나리오 생성, 자동 저장·응답 유실·충돌·초안 복원, 프레임 연결과 업로드 계약, IA 연결, 분석 결과 편집, 결과 선택 추가, XLSX를 확인했다.
- 디자인 시안 브라우저 테스트 13/14 통과. 나머지 1개는 보기 설정을 Escape로 닫은 뒤 트리거 버튼으로 포커스가 돌아오지 않는 기존 문제다. 작업 시작 시점 복사본을 별도 Vite 서버에서 실행해 같은 위치·오류를 재현했다. 이번 명칭 정리에서 포커스 동작은 변경하지 않았다. 웹·플러그인 시안 빌드는 각각 통과했다.
- 390px/데스크톱 실제 캡처에서 테스트 시나리오·상세 목록·분석 결과 편집·관련 자료·테스트 케이스 연결의 명칭과 배치를 선행 레퍼런스의 정보 위계와 대조했다. 사용자 지정 이름 `시트 하나`가 그대로 남는 것도 확인했다.
- 새 마이그레이션은 격리 PostgreSQL에서 검증했다. 업무 데이터가 있으면 중단하고 부분 rename이 남지 않음, 다른 브랜치 테이블이 있으면 초기화 거부, 명시 초기화 후 이력 5개 보존, 전환 후 이력 6개 및 재실행, 모든 구 제약 이름 제거를 확인했다. 초기화·마이그레이션을 서버 시작에 연결하지 않았다.

### 독립 UX 검수

- 지정 `ux-writing-review` 에이전트로 최초 검수 후 3회 재검수했다. 최종 변경 문구 문제 없음.
- 시나리오 연결 버튼에서 이름과 분류를 별도 요소로 나눴고 단위 테스트/통합 테스트를 표시한다. 분석 결과 저장 오류는 응답 유실을 고려해 저장 여부를 단정하지 않고 변경 내용이 화면에 남아 있음을 안내한다.
- 최신 분석 결과와 충돌한 편집 내용을 비교·복구하는 UI가 없는 기존 제한은 이번 명칭 변경에서 확장하지 않았다. 이 제한은 코드와 표시 조건을 확인해 기록했으며 검수도 기존 제한으로 구분했다.
- 시안의 전체 선택 접근성 이름에 현재 표시 항목임을 명시하자는 의견은 선택 제안으로 남겼다. 현재 필터 문맥과 선택 동작은 보존했다. 사용자의 설명문 삭제 재요청이나 검수자의 불필요한 안내 추가 요구는 없었다.

### 로컬 환경과 인계

- 초기 검증에서 Cheddar 로컬 테스트 DB의 업무 테이블을 승인 범위 내 명시 초기화하고 새 migration을 적용했다. 이후 readiness 검사에서 다른 브랜치 migration 이력이 섞여 있음을 발견해 검증 DB를 전용 PostgreSQL(55433)로 분리했다. 공유 테스트 DB의 기존 migration 이력을 삭제하거나 다시 작성하지 않았다.
- 기존 실행 DB와 다른 worktree에서 실행 중인 API(3102)는 초기화·재시작하지 않았다. 이 체크아웃을 실제로 실행할 때에는 다른 브랜치와 공유하지 않는 DB를 지정하고 README의 명시 초기화/마이그레이션 순서를 따라야 한다.
- 작업 시작 전부터 현재 브랜치에 미푸시 커밋 2개와 미커밋 시안·설정 변경이 있었다. 이들을 포함하는 커밋·푸시는 하지 않고 전체 구현을 작업 트리에 유지했다. 시안 소스에는 기존 작업 위에 이번 명칭 변경만 적용했다. PR·병합·배포는 하지 않았다.


## 커밋 분리와 main 반영

사용자는 후속 요청에서 이번 변경의 커밋·푸시·main 병합을 승인했고, main에 없는 분석 결과 편집·생성 결과 검토와 디자인 시안도 별도 선행 커밋으로 함께 반영하도록 선택했다.

- 최신 `origin/main`의 `611923b`를 기준으로 임시 체크아웃에서 `codex/feature-terminology`를 구성했다. 기존 작업 폴더의 브랜치·미커밋 파일은 보존한다.
- 분석·생성 결과 선행 구현 `fc7febc`를 `933f301`로 cherry-pick하고, 작업 시작 시점의 시안·관련 설정만 `7b5662c`로 분리했다. 그 다음 커밋에는 이번 명칭 변경만 포함한다. 다른 작업인 AI 실험 종료 기록은 제외한다.
- 분리된 최종 소스는 앞서 검증한 작업 폴더와 파일 단위로 동일함을 확인했다. API 58개·제품 브라우저 38개·플러그인 13개 및 시안 13/14 결과는 해당 동일 소스의 검증 근거다. 분리 체크아웃에서 정적 검사·타입·빌드를 다시 수행한다.
- 작업 브랜치를 일반 푸시하고 main에는 세 구현 커밋을 보존하는 merge commit으로 반영한다. 원격 SHA는 완료 보고에서 확인한다. 실행 DB 전환·배포는 이 Git 병합에 포함하지 않는다.
