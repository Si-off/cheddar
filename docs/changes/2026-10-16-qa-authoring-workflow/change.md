## 완료 조건과 계획

1. 표 옆에서 관련 원본 이미지와 근거 설명을 검토한다. 원본 위치와 확대/축소를 제공한다.
2. 생성 전에 업로드의 개별 화면을 선택한다. 설명만 생성하는 경로와 빈 시트 작성은 유지한다.
3. 새 UI 생성 결과는 기존 시트를 즉시 덮어쓰지 않는다. 생성 케이스와 후보를 저장하고 기존 케이스와 비교/편집한 뒤 선택 추가한다. 기존 API의 교체 모드는 호환 유지한다.
4. AI가 원본 노드의 화면/상태/설명을 정리하고 관계를 추론한 뒤 케이스를 생성한다. 원문과 이미지 영역을 보존한다. 생성 이후 작은 근거 수정 버튼으로 같은 화면의 수정 영역을 연다. 사용자에게 사전 연결 작업을 요구하지 않는다. 불확실한 화살표 의미는 확정하지 않는다.

사용자 추가 결정: 자동 정리 후 사용자가 잘못된 연결만 수정한다. 페이지 전환은 하지 않는다. 분석 결과를 이미 수정한 프레임은 재생성 때 수정 내용을 우선 사용한다.
5. 후보의 확인 사유를 정책 항목으로 저장하고 사용자 답변을 생성 입력에 연결한다. 프로젝트 규칙 반영은 명시 선택한다.
6. 요구사항별 케이스 연결을 저장하고 실제 연결 누락을 표시한다. AI 검토 제안과 실제 연결을 구분한다.

## 인터페이스와 보존

- 프로젝트 자료 문서는 별도 revision을 가진 JSON 문서로 저장한다. 원본 파일은 수정하지 않는다. 항목/관계/케이스 링크는 프로젝트 소속을 검사한다.
- 생성 요청은 화면 ID와 요구사항 ID 선택, 결과 검토 모드를 추가한다. 결과 추가는 시트와 작업 revision을 함께 검사하고 한 트랜잭션에서 저장한다.
- 현재 허용된 uploads/generation/contracts 및 웹의 project-uploads/test-case-editor 안에 파일을 추가한다. 신규 소스 폴더는 만들지 않는다.
- 사용자의 미커밋 프로토타입과 설정 변경을 보존한다. 저장 충돌/미저장 초안 보호를 유지한다.

## 검증

- API: 다른 프로젝트 참조 거절, revision 충돌, 추출 원문/영역 보존, 선택 프레임만 입력, 결과 검토의 기존 케이스 보존, 중복 추가 방지, 근거 연결.
- UI: 원본 패널, 프레임 선택, 결과 비교/선택 추가, 자료 편집, 정책 답변, 요구사항 연결과 좁은 화면.
- 정적 검사와 빌드, OpenAPI/SDK 재생성, 지정 에이전트 독립 UX 문구 검수.
- 실제 AI 품질, 범용 화면 분리 정확도와 Figma 호스트 검증은 실행 여부와 한계를 별도 보고한다.

## 중단과 인계

- 2026-10-16 사용자 요청으로 신규 기능 구현 중단. 다른 페이지 디자인 개선 후 후속 방향을 결정한다. 이후 사용자가 피처 브랜치 커밋을 승인하여 현재까지 작성한 변경만 작업 중 상태로 커밋한다. 추가 구현과 수정, 푸시는 수행하지 않는다.
- 작성 중인 API, 웹 UI, SDK, 마이그레이션과 문서 변경을 보존한다. 기존 프로토타입 및 다른 작업의 변경은 커밋에서 제외한다. 이 커밋의 기준 HEAD는 다른 작업이 반영된 `da2c9e0`이다.
- 정적 검사와 빌드 통과. 격리 PostgreSQL에서 API 테스트 58개 통과. 브라우저 테스트는 23개 통과, 기존 모바일 가로 넘침 검사 1개 실패로 미해결이다. 실제 AI와 Figma 호스트 검증은 미실행이다.
- 독립 UX 검수는 수정 필요: 기존 결과의 `제외한 후보 보기` 레이블, 근거 저장 충돌의 복구 경로, 생성 결과 편집 충돌의 초안 재적용 경로가 남아 있다. 결과 편집창 종료 시 미저장 초안 보존과 툴바 배치도 추가 확인 대상이다.
- 이 작업이 실행한 웹 개발 서버와 격리 테스트 PostgreSQL을 종료했다. 기존 API 서버는 유지한다. 제품 런타임 DB 적용과 서버 재시작, PR, 병합, 배포는 하지 않았다.
