## 1. 데이터 경계

| 영역 | 저장하는 내용 | 편집 예 | XLSX·CSV |
| --- | --- | --- | --- |
| 테스트 케이스 | 기존 양식, 각 열의 값, 화면 연결, 케이스 순서 | 제목·수행 절차·예상 결과 수정 | 기존 테이블 정의대로 내보냄 |
| 시나리오의 흐름 | 단계, 방향 연결, 분기 조건, 단계와 케이스의 참조 | 배송지 단계 추가, 실패 분기 연결 | 제외 |
| 보기 설정 | 카드 위치, 묶음 접힘, 정렬 방향, 묶음 기준 | 카드 이동, 묶음 접기 | 제외 |

- 테이블은 기본 업무 데이터다. 캔버스 라이브러리의 노드 객체나 좌표를 케이스 본문·사용자 정의 열에 저장하지 않는다.
- 흐름은 캔버스가 없어도 해석할 수 있는 시나리오의 부가 구조다. 선택한 UI 라이브러리의 핸들·포트·픽셀 정보는 흐름 계약에서 제외한다.
- 렌더링 시 `케이스 + 흐름 + 보기 설정`을 조합한다. 표와 내보내기는 흐름·캔버스를 조회하지 않아도 기존 케이스를 사용할 수 있어야 한다.
- 공유하는 케이스는 UUID로 참조한다. 여러 단계에 나타나는 동일 케이스는 본문을 복제하지 않으며 전체 케이스 수와 내보내기 행에서는 한 번만 센다.
- 기능 구분은 기존 사용자 정의 열의 값이다. 묶음 기준은 열 이름 문자열 대신 열 UUID를 참조한다. 사용자 양식에 없는 열을 임의로 추가하지 않는다.
- 기존 데이터 이관 시 케이스를 변경하지 않는다. 흐름과 배치는 없는 상태에서 시작할 수 있다.

### 최소 개념 모델

- `Scenario`: 기존 시나리오와 케이스·양식.
- `FlowStep`: 시나리오 ID, 단계 ID, 제목, 유형(시작/화면/행동/조건/종료), 설명, 선택적 IA 참조.
- `FlowTransition`: 연결 ID, 출발 단계 ID, 도착 단계 ID, 선택적 조건 문구. 순서는 방향 연결로 표현하고 좌표나 단계 배열 순서로 추론하지 않는다.
- `StepCaseLink`: 단계 ID와 케이스 UUID. 같은 쌍의 중복을 허용하지 않는다. 이는 단계와 케이스의 관련성을 뜻하며 자동으로 수행 경로를 확정하지 않는다.
- `CanvasLayout`: 시나리오 ID, 보기 유형, 대상 ID별 위치와 묶음 접힘, 묶음 기준. 반복 표시되는 카드의 배치 키는 단계 ID와 케이스 UUID의 조합이다.

기능 묶음은 선택한 열의 값으로 계산하고 별도 케이스 사본이나 별도 분류 원본을 만들지 않는다. 흐름의 단계와 기능 분류는 다른 개념이다. 동일한 결제 기능이 최초 결제와 재시도 단계에 등장할 수 있다.

## 2. 화면 구성

- 기존 보기 선택에서 표, 상세 보기, 캔버스를 제공한다.
- 캔버스 도구 영역은 `기능별` / `흐름`을 선택한다. 단위 시나리오의 첫 진입은 기능별, 통합 시나리오는 흐름을 제안하되 흐름이 없으면 빈 화면에서 생성·수동 추가 행동을 제공한다. 이후 마지막 선택을 유지한다.
- 상단에는 현재 시나리오, 테스트 검색, 보기 선택, 내보내기를 유지한다. 캔버스 도구는 묶음 기준 또는 단계 추가, 자동 정렬, 실행 취소·다시 실행으로 제한한다.
- 좌측 앱 내비게이션은 기존 구조를 유지한다. 추가 목록 패널은 상시 펼치지 않는다.
- 하단에는 축소·확대, 현재 배율, 전체 보기를 둔다. 전체가 화면을 벗어날 때 미니맵을 열 수 있다.
- 상세 편집은 기존 우측 패널을 확장한다. 단계나 연결선을 선택하면 해당 속성을 같은 패널에서 편집한다.

### 기능별 보기

- 기본 묶음 기준은 사용 가능한 기능 구분 열이다. 해당 열이 없으면 화면 기준을 사용하거나 사용자가 텍스트 열을 선택한다.
- 기능 구분의 같은 값을 하나의 영역으로 모은다. 값이 없는 케이스는 `미분류`에 모은다. 화면이 여러 개 연결된 케이스는 각 화면에서 같은 UUID를 참조할 수 있다.
- 묶음 제목 옆의 개수는 해당 묶음의 고유 케이스 수다. 전체 개수는 시나리오의 고유 케이스 수다.
- 카드에는 케이스 정보 전체를 표시한다. 테스트 ID·제목을 머리말로, 기능 구분·화면·우선순위 같은 짧은 항목을 정보 영역으로, 사전 조건·테스트 데이터·수행 절차·예상 결과를 각각 본문 영역으로 배치한다. 사용자 정의 항목과 관련 화면·자료 참조도 포함하고, 사용자 양식의 이름과 값을 유지한다. 표의 열 숨김 설정으로 카드의 정보를 생략하지 않는다.
- 본문은 요약·말줄임·더 보기·카드 내부 스크롤 없이 줄바꿈하며 카드 높이가 내용에 맞춰 늘어난다. 빈 값은 해당 레이블 아래 `—`로 표시한다. 관련 자료는 자료 이름과 열기 링크를 카드에 두며, 원본 파일 전체를 카드 안에 펼쳐 복제하지 않는다.
- 카드 폭은 읽기 좋은 일정한 폭을 기본으로 제안하고 내용 길이에 따른 높이 차이를 허용한다. 짧은 정보는 2열, 긴 본문은 1열로 구성한다. 확대율에 따라 카드 레이아웃이나 정보량을 다시 구성하지 않는다.
- 읽기 위해 상세 패널을 열 필요가 없어야 한다. 상세 패널은 직접 편집과 원본 자료 확인에 사용한다. 카드 내부에서도 본문 텍스트를 선택해 복사할 수 있고 카드 머리말·드래그 손잡이로 위치를 이동한다.
- 묶음 제목을 드래그하면 내부 카드가 함께 이동한다. 카드 위치 이동은 소속이나 분류 값을 바꾸지 않는다.
- 소속을 바꾸려면 카드 메뉴의 `기능 구분 변경`에서 값을 고른다. 그러면 기존 테이블 셀을 변경하며 표와 내보내기에도 반영된다. 화면 기준일 때는 `관련 화면 변경`으로 다중 연결을 편집한다.
- 첫 범위에서는 자유 이름의 수동 묶음을 별도로 만들지 않는다. 기존 분류 열과 중복되는 데이터 원본을 피한다.

### 흐름 보기

- 업무의 한 단계를 제목이 있는 영역으로 표현하고 관련 케이스를 안에 배치한다. 카드 사이가 아닌 단계 사이를 방향선으로 연결한다.
- 시작·종료는 작은 노드, 화면·행동은 카드 영역, 조건은 작은 조건 노드로 표현한다. 모든 단계가 케이스를 가져야 하는 것은 아니다.
- 조건의 출구에는 `결제 성공`, `결제 실패`처럼 의미 있는 조건을 붙인다. 합류와 재시도 연결을 지원하며 순환을 오류로 취급하지 않는다.
- 예시: 시작 → 주문 확인 → 결제 → 결제 결과. 성공은 주문 완료로, 실패는 결제 재시도로 이어지고 결제 재시도에서 결제로 돌아온다.
- 단계를 선택하면 제목·유형·관련 화면·연결된 케이스를 직접 편집한다. 기존 케이스 연결과 새 케이스 추가를 구분한다.
- 연결선을 선택하면 출발·도착·조건을 편집하거나 연결만 삭제한다. 패널의 선택 입력으로도 연결을 만들 수 있어 작은 연결점을 반드시 드래그할 필요가 없다.
- 같은 케이스를 여러 단계에 연결할 수 있다. 같은 UUID의 내용을 어디서 편집하든 모든 표시가 갱신된다.
- 흐름 보기의 카드도 기능별 보기와 동일한 전체 정보 구성을 사용한다. 흐름을 한 화면에 맞추려고 제목만 있는 카드로 바꾸지 않는다. 전체 구조는 줌아웃으로, 각 단계의 케이스는 줌인으로 읽는다.
- 단계에 연결되지 않은 케이스는 `연결 안 된 케이스`에서 찾고 직접 연결한다. 이것을 테스트 누락이나 오류라고 판정하지 않는다.
- 흐름은 시나리오의 전체 진행 구조다. 개별 통합 케이스의 정확한 수행 절차는 기존 본문이 원본이다. 케이스별 경로 저장·실행 추적은 첫 범위에서 제외하며 관련 단계만으로 경로를 확정해 강조하지 않는다.

## 3. 조작 규칙

| 조작 | 제안 동작 |
| --- | --- |
| 캔버스 위 마우스 휠 | 포인터 위치를 중심으로 확대·축소 |
| 트랙패드 두 손가락 / 핀치 | 화면 이동 / 확대·축소 |
| 빈 공간 드래그, Space+드래그 | 화면 이동 |
| 카드 머리말·손잡이 드래그 | 해당 묶음 안에서 카드 위치 이동. 본문 드래그는 텍스트 선택이며 분류나 단계 연결은 유지 |
| 묶음·단계 제목 드래그 | 영역과 소속 카드 함께 이동 |
| Shift+선택, 선택 도구 드래그 | 여러 카드·단계 선택 |
| 자동 정렬 | 기능별은 카드와 묶음을 격자로, 흐름은 연결 방향으로 배치. 재시도 연결도 보존 |
| 선택 정렬 | 선택한 카드 정렬·간격 맞춤. 의미와 내보내기 순서 유지 |
| 전체 보기 / 선택 보기 | 전체 또는 선택한 대상이 화면에 들어오도록 확대율·중심 조정 |
| 실행 취소 / 다시 실행 | 내용·연결·배치별 명령을 현재 편집 세션에서 되돌림 |

- 자동 정렬은 명시적 실행 때만 전체 배치를 바꾼다. 새 AI 결과나 케이스 추가는 기존 수동 배치를 유지하고 새 항목만 가까운 빈 공간에 둔다. 정렬 한 번은 실행 취소 한 번으로 복구한다.
- 확대·축소는 동일한 카드 전체를 기하학적으로 확대·축소한다. 배율에 따른 항목 숨김·요약·본문 접힘·카드 재배치는 하지 않는다. 줌아웃에서는 전체 분포와 연결을, 줌인에서는 한두 케이스의 모든 내용을 읽는다. 전체 보기는 전체 영역에, 선택 보기는 선택한 한두 카드에 맞춰 배율과 중심을 계산한다. 축소 하한을 먼저 고정해 전체 보기를 방해하지 않는다.
- 내용 편집으로 카드가 커지면 아래 카드가 겹치지 않도록 해당 묶음 안에서 필요한 간격만 확보한다. 다른 묶음과 전체 흐름을 자동 정렬하지 않는다. 수동 정렬 시에도 실제 카드 높이를 반영한다.
- 검색은 우선 일치 카드와 해당 묶음을 강조하고 결과로 이동한다. 연결된 단계를 숨겨 흐름이 끊긴 것처럼 보이지 않게 한다.
- 연결·선택 모드와 이동 모드를 도구로 구분한다. 상세 패널·입력창의 휠은 해당 영역 스크롤로 처리한다.
- 키보드로 카드와 단계 선택, 상세 편집, 연결 대상 변경, 정렬과 확대 조절을 제공한다. 기존 표·상세 보기에서도 케이스 본문을 계속 편집할 수 있다.

## 4. 직접 편집과 삭제

- 카드 본문을 수정하면 기존 케이스 자동 저장 경로를 사용한다. 표에서도 같은 내용을 즉시 볼 수 있다.
- 흐름 제목·조건·연결 변경은 흐름만 저장한다. 케이스 본문을 자동으로 다시 쓰거나 AI를 호출하지 않는다.
- 흐름 변경 이후 관련 케이스를 선택해 확인할 수 있다. 변경 사실만으로 모든 케이스에 경고 배지를 붙이거나 내용이 틀렸다고 판단하지 않는다.
- 단계의 카드에서 `연결 해제`는 StepCaseLink만 제거한다. 케이스 자체를 없애는 `테스트 케이스 삭제`와 메뉴를 구분한다.
- 단계 삭제는 해당 단계·인접 연결·케이스 연결만 제거한다. 연결된 실제 케이스는 남긴다. 삭제 전에 제거될 연결 수와 케이스가 유지됨을 확인한다.
- 케이스 삭제는 표와 모든 흐름 참조에서 사라지므로 연결 수를 확인한다. 삭제와 참조 정리는 한 저장 작업으로 처리한다.
- 자유 배치와 정렬은 서버의 케이스 순서·분류 값을 변경하지 않는다.

## 5. AI 생성

### 신규 시나리오

1. 사용자가 기존 생성 입력에서 화면 자료와 설명을 선택한다.
2. 케이스 생성과 함께 흐름 초안을 받을 수 있다. AI 출력은 케이스, 단계, 연결, 케이스 참조로 분리한다. 픽셀 좌표는 AI에게 맡기지 않고 앱이 배치한다.
3. 생성 결과 검토에서 케이스와 흐름을 확인한다. 방향·조건·제목·참조를 직접 고치고 선택한 결과를 반영한다.
4. 기존 검토 후보 정책을 유지한다. 불확실한 관계의 근거와 확인할 항목은 검토 영역에서 확인하고, 미확정 정책을 사실인 연결 조건으로 저장하지 않는다.

### 기존 시나리오

- `흐름 생성`은 저장된 케이스와 연결 자료를 입력으로 단계와 연결 초안을 만든다. 기존 케이스 내용·분류·현재 흐름은 완료 즉시 교체하지 않는다.
- 초안은 별도의 미리보기로 제공한다. 사용자는 단계·연결을 직접 수정하고 새 초안을 반영할지 결정한다.
- 기존 흐름이 있으면 반영 시 교체될 범위와 현재 흐름 복구 방법을 제공한다. 첫 범위는 흐름 전체 교체이며 AI 자동 부분 병합을 도입하지 않는다. 교체 시 흐름 보기의 배치도 초안 배치로 바뀐다. 기능별 보기의 배치는 유지한다. 교체 직전 흐름과 흐름 보기 배치를 한 세대의 복원본으로 저장하고, 흐름 메뉴의 `이전 흐름 복원`에서 다시 열어 본 뒤 복원할 수 있다. 복원도 현재 흐름 revision과 케이스 참조를 검증하며 삭제된 케이스를 재생성하지 않는다. 복원본은 서버에 보관해 새로고침 이후에도 사용할 수 있게 제안한다.
- 초안 생성 중에도 기존 흐름을 열람할 수 있다. 반영 직전에 케이스·흐름 revision을 비교하고 생성 이후 달라진 내용을 덮어쓰지 않는다. 충돌 시 변경된 항목과 최신 상태를 다시 확인한다.
- 선택하지 않은 생성 케이스에 대한 참조를 그대로 저장하지 않는다. 반영할 케이스 집합에 맞춰 참조를 검증한다.
- 수동 수정은 모델 호출·토큰 비용·AI 응답 대기 없이 가능하다. AI 요청에 의한 자연어 수정 기능은 이번 범위에 포함하지 않는다.

## 6. 저장과 내보내기

- 케이스는 기존 내용 revision, 흐름은 별도 revision, 배치는 별도 revision을 제안한다. 드래그 이벤트마다 케이스 전체를 저장하지 않는다.
- 초기 권한·개인 설정 모델이 없으므로 수동 배치는 시나리오 공통 배치로 저장하는 안을 제안한다. 확대율·현재 중심·선택은 브라우저의 시나리오별 설정으로 두며 다른 사용자의 화면을 이동시키지 않는다. 향후 개인별 배치는 별도 결정이다.
- 저장 실패 시 해당 종류의 미저장 입력을 유지하고 재시도한다. 케이스 저장 성공을 근거로 흐름이나 배치까지 저장되었다고 표시하지 않는다.
- 케이스 삭제처럼 여러 원본을 건드리는 작업은 참조 정리까지 원자적으로 처리한다. 배치 저장 실패가 케이스 데이터 손실로 이어지지 않는다.
- XLSX·CSV는 시나리오의 저장된 전체 테이블 데이터를 기존 양식의 열 이름·순서로 내보낸다. 현재 검색, 접힘, 확대율, 캔버스 좌표, 단계 연결 여부, 카드의 반복 표시를 반영하지 않는다.
- 기능 구분이나 케이스 본문처럼 실제 테이블 값을 수정한 것은 내보내기에 반영된다. 단계·조건·연결·좌표를 열에 덧붙이거나 별도 시트·파일·ZIP으로 내보내지 않는다.
- 내보내기 시 미저장 테이블 변경은 저장 완료 후 내보내거나 저장 실패를 처리한다. 흐름·배치만 미저장인 것은 테이블 내보내기를 막지 않는다.

## 7. 첫 구현 범위와 후속

첫 구현을 완성하는 순서는 다음과 같이 제안한다. 중간 단계가 전체 요구 충족을 의미하지 않는다.

1. 케이스와 독립적인 흐름·참조·배치 계약 및 저장, 기존 데이터 호환, 참조 검증.
2. 기능별 캔버스, 이동·확대·선택·정렬, 기존 상세 편집 연동.
3. 흐름 단계·분기·합류·재시도, 케이스 연결, 직접 편집·삭제·실행 취소.
4. AI 흐름 생성, 검토·반영·충돌 처리. 신규 케이스 생성 결과와 연결.
5. 테이블 내보내기 불변성, 저장 복구, 규모·키보드 조작 검증.

후속으로 남길 것은 케이스별 실행 경로 저장, 실제 QA 수행 결과, 실시간 공동 편집, 개인별 레이아웃, 무제한 중첩 묶음, AI 부분 병합, 캔버스 이미지/PDF 내보내기다. 프로젝트 전용 기능 데이터의 XLSX·CSV 내보내기는 제안하지 않는다.

## 8. 이미지 시안 명세와 문구

공통: 밝은 중립 배경, 흰 카드, 보라색 #515299 강조, Noto Sans KR 계열. 캔버스는 넓게 쓰고 긴 기능 설명·개발 상태 배지·저장 성공 표시는 넣지 않는다. 이미지의 데이터는 예시이며 실제 API·저장과 연결되지 않는 시각 제안이다. 이미지 내부에 이를 설명하는 배너를 추가하지 않는다.

아래 A/B는 최초 제안의 기록이다. 사용자 피드백 이후 두 시안의 요약 카드 표현은 채택하지 않는다. 묶음·흐름·연결 편집 구성은 유지하고 카드 표현은 C의 전체 정보 카드로 대체한다.

### 시안 A: 기능별 전체 탐색

- 제목: `쇼핑몰 QA`, `기본 기능 테스트`.
- 보기 선택: `표`, `상세 보기`, `캔버스`(선택).
- 도구: `테스트 검색`, `기능별`(선택), `흐름`, `묶음 기준`, `기능 구분`, `자동 정렬`, `케이스 추가`, `내보내기`.
- 총 10개 케이스를 3개 영역에 표시: `로그인` 3개, `상품 탐색` 3개, `장바구니` 4개. 두 행의 균형 잡힌 카드와 넓은 영역 간 여백으로 묶음을 보여준다.
- 카드 예: UT-001 정상 로그인 / 홈 화면으로 이동, UT-002 비밀번호 오류 / 오류 메시지 표시, UT-003 필수값 누락 / 입력 항목 안내, UT-004 상품 검색 / 검색 결과 표시, UT-005 검색 결과 없음 / 빈 결과 표시, UT-006 상품 상세 / 상품 정보 표시, UT-007 상품 담기 / 장바구니에 추가, UT-008 수량 변경 / 합계 금액 갱신, UT-009 상품 삭제 / 선택 상품 제거, UT-010 품절 상품 / 주문 불가 안내.
- 하단: `80%`, `전체 보기`, 실행 취소·다시 실행 아이콘. 상시 조작 설명문 없음.
- 이 화면은 묶음과 카드의 자유 배치·정렬 가능성을 보여준다. 기능 분류 영역 사이에 의미 없는 진행 화살표를 그리지 않는다.

### 시안 B: 통합 흐름과 연결 직접 편집

- 제목: `쇼핑몰 QA`, `주문 결제 테스트`.
- 보기 선택: `표`, `상세 보기`, `캔버스`(선택).
- 도구: `테스트 검색`, `기능별`, `흐름`(선택), `단계 추가`, `흐름 생성`, `자동 정렬`, `내보내기`.
- 시작 → 주문 확인 → 결제 → 조건 `결제 결과`. `결제 성공`은 주문 완료로, `결제 실패`는 결제 재시도로 연결한다. 결제 재시도에서 결제로 `다시 결제` 연결이 돌아온다. 실제 수행 완료 상태를 나타내는 체크마크·녹색 통과 배지는 사용하지 않는다.
- 카드 예: IT-001 정상 주문 결제, IT-002 결제 실패 후 재시도. 같은 IT-002가 결제와 재시도 단계에서 보일 수 있다.
- `결제 실패` 연결을 보라색으로 선택하고 오른쪽 직접 편집 패널을 연다. 제목 `연결 편집`, 필드 `출발 단계`=`결제 결과`, `도착 단계`=`결제 재시도`, `조건`=`결제 실패`. 하단 `연결 삭제`, 우상단 닫기 버튼.
- 패널은 일반 선택 입력·텍스트 입력으로 구성한다. AI 채팅 입력, 프롬프트 편집 UI, AI 수정 요청 버튼을 넣지 않는다.
- 저장 방식 제안은 자동 저장이므로 별도 적용 버튼과 저장 완료 표시를 그리지 않는다. 생성 초안 반영 화면과 혼동하지 않는다.
- 하단: `75%`, `전체 보기`, 실행 취소·다시 실행 아이콘. 연결에 반복 문구를 넣거나 화살표를 케이스의 수행 절차라고 표현하지 않는다.
- B는 기존 흐름의 수동 편집 상태다. AI 초안 검토 상태와 복원 메뉴는 이 이미지에 함께 펼치지 않는다.

### 시안 C: 전체 정보 카드 두 개를 확대해서 읽기

- A와 같은 앱 프레임과 기능별 캔버스에서 `로그인` 묶음을 확대해 두 카드를 나란히 읽는다. 우측 상세 패널은 닫고 카드 자체에 모든 예시 정보를 표시한다. 하단 배율 `100%`, `전체 보기`와 `선택 보기`, 전체 분포가 보이는 미니맵을 둔다.
- 카드 공통 레이블: `기능 구분`, `화면 ID`, `우선순위`, `사전 조건`, `테스트 데이터`, `수행 절차`, `예상 결과`, `관련 자료`. ID와 제목은 카드 머리말. 짧은 항목은 2열, 긴 항목은 1열로 자연스럽게 구분한다.
- UT-001 `정상 로그인`: 기능 구분 `로그인`, 화면 ID `AUTH-01`, 우선순위 `높음`. 사전 조건 `가입이 완료된 계정이 있다. 로그아웃 상태다.` 테스트 데이터 `이메일: qa@example.com`과 `비밀번호: Test1234!`. 수행 절차 `1. 로그인 화면에 진입한다.\n2. 이메일과 비밀번호를 입력한다.\n3. 로그인 버튼을 누른다.` 예상 결과 `홈 화면으로 이동한다.\n사용자 이름이 표시된다.\n새로고침 후에도 로그인 상태가 유지된다.` 관련 자료 `로그인 화면`.
- UT-002 `비밀번호 오류`: 기능 구분 `로그인`, 화면 ID `AUTH-01`, 우선순위 `보통`. 사전 조건 `가입이 완료된 계정이 있다. 로그아웃 상태다.` 테스트 데이터 `이메일: qa@example.com`과 `비밀번호: Wrong123!`. 수행 절차 `1. 로그인 화면에 진입한다.\n2. 이메일과 잘못된 비밀번호를 입력한다.\n3. 로그인 버튼을 누른다.` 예상 결과 `비밀번호 오류 메시지가 표시된다.\n로그인 화면에 머문다.` 관련 자료 `로그인 화면`.
- 두 카드의 높이는 실제 본문 길이에 맞게 다르게 둔다. 공간을 채우려고 문장을 반복하거나 임의 내용을 늘리지 않는다. 내부 스크롤바, 말줄임, 요약 배지, 더 보기 버튼은 없다.
- 이미지 생성 입력에는 기존 앱 스타일을 참고하되 카드의 정보 위계와 전체 본문 노출을 최우선으로 지정한다. 이 시안은 확대 상태 하나를 보여주며 미니맵은 위치 탐색 장치다. 축소 상태의 카드도 같은 정보를 그대로 축소해 보여주는 계약이다.

### AI 초안 검토 상태의 화면 계약

- 이미지 A/B 밖의 후속 화면 명세다. `흐름 생성` 완료 시 기존 편집기와 구분되는 검토 화면에 제목 `생성된 흐름 검토`와 `현재 흐름 보기`를 둔다.
- 검토 화면의 단계·연결·참조도 우측 패널로 직접 수정한다. 이때 편집하는 대상은 초안이며 현재 흐름은 유지된다.
- 하단에는 `취소`와 `흐름 추가`(기존 흐름 없음) 또는 `현재 흐름 교체`(기존 흐름 있음)를 둔다. 교체는 아래 확인 단계를 거친다.
- 현재 흐름과 초안은 동일한 줌으로 비교할 수 있지만 자동 합치기는 제공하지 않는다. 실제 화면 배치와 전환은 구현 전 시안에서 별도로 확인한다.
- 교체 이력이 있을 때 흐름 메뉴에 `이전 흐름 복원`을 표시한다. 일반 편집기의 실행 취소와 별개이며, 복원 전후의 흐름을 확인한 다음 반영한다.
- 복원본의 케이스가 이미 삭제되었으면 해당 케이스 참조만 제외한다. 복원 전 제외될 테스트 ID·제목과 `삭제된 테스트 케이스 {n}개는 연결하지 않고 복원합니다.`를 표시하고 `취소` 또는 `복원`을 선택한다. 단계·연결 구조는 유지하며 실제 케이스를 재생성하지 않는다. 사용자가 확인한 뒤에도 상태가 달라지면 다시 검토한다.

### 상황별 필수 문구와 표시 조건

| 상황 | 문구·행동 | 표시 조건 |
| --- | --- | --- |
| 흐름 없음 | `흐름이 없습니다` / `흐름 생성` / `단계 추가` | 저장된 흐름의 단계가 없을 때 |
| 단계에 케이스 없음 | `케이스 연결` | 화면·행동 단계에서 기존 케이스 선택을 열 때 |
| 단계 삭제 확인 | `단계 삭제` / `흐름 연결 {n}개 삭제`, `테스트 케이스 {m}개 연결 해제`, `테스트 케이스는 유지됩니다.` / `취소` / `삭제` | 연결이나 케이스 참조가 있는 단계 삭제 직전. 0개인 영향 항목은 표시하지 않음 |

## 9. 구현 시 검증 기준

- 같은 케이스를 표·두 흐름 단계에서 편집해도 하나의 값과 내보내기 행만 유지되는가.
- 카드 이동·정렬·접기·배율 변경 전후에 테이블 값·순서·내보내기 값이 동일한가. XLSX ZIP 바이트 대신 셀 값·열 순서·행 수를 비교한다.
- 단계·연결 변경만으로 케이스 본문·분류·내보내기가 달라지지 않는가.
- 기능 구분 변경은 기존 셀과 캔버스 묶음에 함께 반영되는가. 열 이름 변경에도 같은 열 UUID를 계속 참조하는가.
- 단계 삭제는 케이스를 남기고 실제 케이스 삭제는 모든 참조를 함께 정리하는가.
- 재시도 순환·조건 분기·합류가 정렬과 저장 후에도 보존되는가.
- AI 실패·부분 선택·동시 변경·잘못된 참조가 기존 케이스나 수동 흐름을 덮어쓰지 않는가.
- 케이스·흐름·배치 각각의 저장 실패와 다시 열기, 실행 취소를 검증하는가.
- 500개 케이스와 반복 참조가 있는 화면에서 첫 표시·확대·드래그·검색 반응을 측정하는가. 측정 전 성능 수치를 보장하지 않는다.
- 마우스 휠과 트랙패드, 상세 패널 스크롤, 키보드 입력, 좁은 화면에서 조작이 충돌하지 않는가.
- 긴 수행 절차, 긴 예상 결과, 사용자 정의 항목을 포함한 케이스 정보가 카드에서 잘림 없이 모두 노출되는가. 확대율을 바꿔도 항목·값·순서가 유지되는가.
- 카드 높이 변화와 자동 정렬 후 카드·연결선이 겹치지 않는가. 본문 복사와 카드 이동이 충돌하지 않는가.

## 완료와 인계

- 전체 정보 카드와 기능별 묶음, React Flow 탐색·선택·이동, ELK 자동 정렬, 흐름 단계·연결 직접 편집, 실행 취소·다시 실행을 구현했다.
- 케이스 저장, 흐름·배치 저장, 별도 AI 흐름 작업·검토·교체·이전 복원을 연결했다. 본문 사본이나 구형 고정 필드 호환 계층은 추가하지 않았다.
- 기존 케이스 생성·추가 방식과 테이블 내보내기 계약을 유지했다. CSV 신규 구현·흐름/배치 내보내기는 제외했다.
- 확정된 제품·구조는 `docs/product.md`, `docs/architecture.md`에 반영했다. 위 1~9절은 초기 제안 및 이미지 제작 이력이며 충돌 시 상단 승인된 구현 계약이 우선한다.
- 다른 작업의 `docs/ux-writing.md`와 AI 실험 종료 기록은 수정·커밋 대상에서 제외했다. 캔버스 변경만 현재 브랜치에 커밋하고 일반 푸시한다. PR·병합·배포는 하지 않는다.
- 실제 AI 제공자 호출은 별도 확인이 필요하다. 자동화 검증 통과와 실제 AI 생성 성공을 동일하게 보고하지 않는다.
