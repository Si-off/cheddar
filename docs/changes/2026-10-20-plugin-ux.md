# 작업: 플러그인 계정 메뉴와 프로젝트 선택

여러 세션에 걸치는 작업에만 만든다. 파일명은 `YYYY-MM-DD-name.md`. 끝나면 삭제한다.

## 목표

플러그인에서 로그아웃하고, 업로드 전에 프로젝트를 고르고, 올릴 수 없는 이유를 업로드 전에 알게 한다. 시안은 [Cheddar 화면 시안](https://claude.ai/artifact/LBfqbThAA8AGkkAYd8BNdA)의 Figma 플러그인 페이지 "개선안" 줄이다.

사용자 결정(2026-10-20):

- 프로젝트 선택은 필수다. 지난번 고른 프로젝트를 기본값으로 둔다.
- 기존 확정 사항 "플러그인은 프로젝트와 업로드 이름 없이 프레임만 올린다"(product.md 임시 업로드)를 "프로젝트를 골라 올린다"로 바꾼다. 업로드 이름은 계속 없다.

포함:

- 머리글 계정 메뉴: 이름과 이메일, Cheddar 열기, 로그아웃.
- 업로드 화면 맨 위 프로젝트 Select. 고르기 전에는 업로드 버튼을 막는다.
- 업로드 권한이 없거나 고를 프로젝트가 없으면 배너로 알리고 업로드 버튼을 막는다. 지금은 프레임을 다 읽은 뒤 403 토스트로 알린다.
- 서버에 연결하지 못하면 "서버에 연결하지 못했습니다" 화면. 지금은 "계정을 확인하지 못했습니다"로 묶여 있다.
- 업로드 완료 화면에 연 프로젝트 이름.
- 웹 새 테스트 세트가 플러그인이 고른 프로젝트를 미리 고른 채 열린다.

제외: 설명 번호 연결, 변경 표시, 배포용 네트워크 허용과 Origin 정책, 가로 타일.

## 설계

프로젝트는 임시 업로드에 저장하지 않고 웹 주소로 넘긴다(`/test-sets/new?upload=<id>&project=<id>`). 업로드 스키마와 생성 흐름은 그대로 두고, 웹 폼은 지금처럼 프로젝트를 바꿀 수 있다.

| 영역 | 변경 |
| --- | --- |
| API | `GET /api/v1/projects`에 `@AllowPluginToken()`, `common/plugin-cors.ts` 허용 목록에 추가. 플러그인 토큰으로 다른 프로젝트 경로는 계속 401인지 테스트 |
| 플러그인 SDK | `pnpm gen:api:plugin` 다시 생성 |
| 플러그인 protocol, main | 지난 프로젝트 ID를 `figma.clientStorage`에 읽고 쓰는 메시지(UUID 검사). 웹 첫 화면을 여는 메시지. `open-upload-web`에 `projectId` 추가 |
| 플러그인 UI | 계정 메뉴(`Menu`), 로그아웃은 `revokePluginConnection` 뒤 로컬 토큰 삭제(네트워크 실패여도 로컬은 지움). 업로드 화면 `Select size="sm"`. 고를 수 있는 프로젝트는 `/me` 권한의 `test_set.create`로 거른다(웹 `create-test-set`과 같은 규칙). `plugin.upload`가 없으면 배너. 기억한 프로젝트가 목록에 없으면 비워 두고, 고를 수 있는 프로젝트가 하나면 그것을 고른다 |
| 웹 | `router.tsx` `uploadSearch`에 `project`(UUID) 추가, `CreateTestSetForm`의 처음 값으로 넘김. 고를 수 없는 프로젝트면 무시 |
| 문서 | product.md 임시 업로드와 플러그인 연결, architecture.md 플러그인 토큰 허용 경로(204행)와 Figma 플러그인 절, DESIGN.md 플러그인 머리글 |

## 현재 상태

브랜치 `claude/plugin-ux`, 기준 `main`(f30b1d2). 구현과 리뷰 반영을 마치고 커밋했다. 플러그인 UI는 빌드 결과를 가짜 main과 가짜 API로 띄워 라이트와 다크로 확인했다. 실제 Figma 안에서는 확인하지 않았다.
