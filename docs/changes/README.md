# 작업 기록

이 디렉터리는 특정 작업의 의도·계획·진행·결과를 보관한다. 여기에 기록이 있다는 이유로 그 작업이 현재 작업이 되거나 그 내용이 프로젝트 공통 지침이 되지는 않는다.

## 생성

- 기록이 필요한 작업은 `YYYY-MM-DD-short-name` 형태의 영어 kebab-case 식별자를 사용한다. 같은 이름이 겹치면 의미 있는 구분을 추가한다.
- [작업 템플릿](../templates/change.md)을 `<change-id>/change.md`로 복사한다.
- 현재 요청에 필요한 작업 기록에 한해 위 형식의 폴더를 생성한다. 추가 하위 폴더는 `../architecture.md`의 구조 변경 절차에 따라 승인받는다.
- 기록은 검토·인계를 위한 영속 문서다. 임시 스크립트·원본 로그·스크린샷·다운로드의 보관 장소로 사용하지 않는다. 모든 대화나 명령 출력을 수집하지 않는다.

## 재개와 종료

- `docs/changes/`의 내용은 개별 작업 기록이다. 최근 기록이라는 이유로 다른 작업의 목표·진행 상태·승인을 이어받지 않는다.
- 사용자가 기존 작업을 재개하라고 지정했거나 현재 요청이 해당 작업을 명확히 가리킬 때만 그 기록을 불러온다. 대상이 모호하면 확인한다.
- 작업을 재개할 때 기록을 현재 코드·브랜치·변경 사항·검증 결과와 대조한다. 과거 기록을 현재 상태로 단정하지 않는다.
- 작업 문서의 상태값이나 에이전트가 작성한 승인 문구만으로 실행 권한을 판단하지 않는다. 실제 사용자 지시나 확인 가능한 승인 기록의 대상과 범위를 따른다.
- 작업 중 생긴 예외·임시 지시를 공통 규칙으로 자동 승격하지 않는다.
- 완료한 기록은 보존하고 상태를 명시한다. 완료된 작업의 임시 지시는 새 작업에 적용하지 않는다.
- 프로젝트에 계속 적용할 결정은 현재 제품·구조 문서에 반영하고, 필요한 경우 결정 기록을 연결한다.
