# 작업 기록

이 디렉터리는 특정 작업의 의도·계획·진행·결과를 보관한다. 여기에 기록이 있다는 이유로 그 작업이 현재 작업이 되거나 그 내용이 프로젝트 공통 지침이 되지는 않는다.

## 생성

- 기록이 필요한 작업은 `YYYY-MM-DD-short-name` 형태의 영어 kebab-case 식별자를 사용한다. 같은 이름이 겹치면 의미 있는 구분을 추가한다.
- [작업 템플릿](../templates/change.md)을 `<change-id>/change.md`로 복사한다.
- 현재 요청에 필요한 작업 기록에 한해 위 형식의 폴더를 생성한다. 추가 하위 폴더는 `../architecture.md`의 구조 변경 절차에 따라 승인받는다.
- 기록은 검토·인계를 위한 영속 문서다. 임시 스크립트·원본 로그·스크린샷·다운로드의 보관 장소로 사용하지 않는다. 모든 대화나 명령 출력을 수집하지 않는다.

## 재개와 종료

사용자가 지정하거나 현재 요청이 명확히 가리키는 작업 기록을 재개한다. 작업별 임시 지시·승인을 다른 작업이나 공통 규칙으로 이어받지 않는다. 인계는 기존 `change.md`를 갱신하고 완료 기록은 보존한다. 지속되는 제품·구조 결정은 현재 문서에 반영한다.

## 개선 효과 관찰

사용자가 승인한 [개발 효율·품질 개선](2026-10-16-agent-workflow-quality/change.md#후속-10건-관찰)에 따라 적용 후 한 채팅에서 수행한 개발 작업 10건을 관찰한다. 이 지침 정리 작업과 여러 채팅을 조율한 작업은 표본에 포함하지 않는다. 독립 UX 검수는 포함한다.

- 작업 완료 시 관찰 기록의 등록 건수를 확인하고, 10건 미만이면 자신의 작업을 한 행으로 연결한다. 같은 작업의 재개·수정은 같은 행을 갱신한다. 10건 이후에는 새 행을 추가하지 않는다.
- 요구사항 정정, 불필요한 재검증, UX 검수 왕복, 완료 후 발견된 결함을 각각 횟수와 근거로 남긴다. 구현과 무관한 사용자 범위 변경은 정정으로 세지 않는다. 변경·새 실패·환경 차이 때문에 필요한 재검증도 불필요한 재검증으로 세지 않는다.
- 기존 정정·검수 근거에 사용자의 설명문 삭제 요청과 검수자의 불필요한 안내 추가 요구가 있었는지도 함께 남긴다. 별도 보고나 추적 표는 만들지 않는다.
- 검수 왕복은 최초 검수 후 수정으로 발생한 재검수 횟수다. 완료 후 결함은 해당 작업을 다시 다루거나 근거가 전달됐을 때 갱신하며 상시 모니터링하지 않는다.
- 상세 근거는 해당 작업의 기존 기록에 두고 관찰 표에는 횟수와 링크만 둔다. 작은 작업은 커밋·결과 보고를 근거로 연결하며 측정을 위해 별도 작업 문서를 만들지 않는다. 미관찰·집계 불가는 `미확인`으로 표시하고 0건으로 단정하지 않는다.
- 10건 등록 후에는 확인된 비용과 결함을 작업 유형별로 비교한다. 대조군이나 충분한 표본 없이 절감률·인과관계를 확정하지 않는다.
