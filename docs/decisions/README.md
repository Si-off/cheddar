# 결정 기록

중요한 제품·구조·운영 선택의 이유를 남긴다. 현재 제품과 구조는 각각 `product.md`, `architecture.md`에서 확인한다. 과거 결정을 새 작업의 실행 승인으로 사용하지 않는다.

## 작성 기준

대안과 선택 이유가 이후 작업의 일관성에 영향을 줄 때 작성한다. 작은 구현 선택마다 만들지 않는다. 파일명은 `YYYY-MM-DD-short-name.md` 형태의 영어 kebab-case를 사용한다.

각 기록에는 다음을 포함한다.

- 제목과 상태: 제안 / 채택 / 기각 / 대체됨
- 배경과 결정해야 할 문제
- 검토한 대안과 영향
- 실제 결정, 이유, 결정 일자와 근거
- 적용 범위와 재검토 조건
- 관련 현재 문서·작업·PR 링크

사용자가 결정하기 전에는 `제안` 상태로 유지한다. 새 결정이 이전 결정을 대체하면 양쪽 기록을 연결하고 현재 문서를 갱신한다. 과거 기록을 삭제해 결정 경위를 없애지 않는다.

아직 별도 결정 기록은 없다. 대화에서 이미 확정된 저장소 운영과 필요한 구성요소는 현재 문서에 반영되어 있다.
