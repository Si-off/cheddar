# pi 생성 실험

기존 생성기를 보존한 `codex/pi-agent-experiment` 브랜치에서 실행한다. 실험 결과를 검토하기 전 main에 병합하거나 배포하지 않는다.

## 사용 흐름

1. 프로젝트의 양식에서 결과에 사용할 열을 설정한다. 이 설정은 현재 웹 기능을 쓴다.
2. 운영자가 해당 프로젝트의 기준 QA XLSX와 사용할 시트를 한 번 등록한다.
3. 이후 사용자는 기존 Figma 플러그인에서 프레임을 선택하고 웹에서 생성한다. 스프레드시트를 매번 전달하지 않는다.

기준 문서 등록은 이번 실험에서 CLI로 제공한다. 프로젝트 설정에 등록 화면을 추가하는 작업은 포함하지 않았다.

```sh
pnpm --filter @cheddar/api qa:reference --project <프로젝트-UUID> --file /절대/경로/기준-QA.xlsx --sheet '916 QA'
```

`--sheet`는 여러 번 지정할 수 있고 생략하면 모든 시트를 등록한다. 같은 프로젝트에 다시 실행하면 이후 생성에 사용할 기준 문서를 교체한다. 진행 중인 작업은 요청 당시 사본을 계속 쓴다. `--project <UUID> --remove`는 연결을 해제한다. 문서 등록은 프로젝트의 열을 자동 변경하지 않는다.

기준 문서가 없는 프로젝트에서는 기존에 수집하던 최근 케이스 예시를 참고한다. 자동으로 편집 이력을 학습하거나 다른 프로젝트의 사례를 섞지 않는다.

## 로컬 실행

Node와 pnpm은 `.nvmrc`, 루트 `package.json`의 버전을 쓴다. 별도 PostgreSQL DB와 파일 저장 경로를 마련하고 `apps/api/.env.local`을 설정한다. 기존 DB에 실험 마이그레이션을 적용하지 않는다. 필수 환경변수는 README와 `.env.example`을 따른다.

```dotenv
AI_GENERATION_ENGINE=pi
AI_PI_MODEL=openai:gpt-6.1-sol
AI_PI_MAX_TURNS=80
AI_PI_MAX_TOKENS=1000000
AI_PI_TIMEOUT_SECONDS=1200
```

```sh
pnpm install --frozen-lockfile
pnpm db:migrate
pnpm --filter @cheddar/api admin:create --login-id pi-demo --name "실험 관리자"
pnpm dev:api
pnpm dev:web
pnpm dev:plugin
```

각 dev 명령은 별도 터미널에서 실행한다. 포트를 기존 개발 환경과 분리하면 웹과 플러그인의 `VITE_API_BASE_URL`, 플러그인의 `VITE_WEB_BASE_URL`, API의 `CORS_ORIGINS`도 맞춘다. Figma에는 **이 워크트리**의 manifest를 개발 플러그인으로 등록한다. 다른 체크아웃의 플러그인은 이전 API 주소를 사용한다.

실제 모델 호출에는 서버의 API 키가 필요하다. `AI_PROVIDER=fake`에서 pi의 실제 실행은 금지되며 테스트는 주입한 합성 실행기로 도구와 저장 동작을 확인한다. 다시 작성과 열 채우기는 기존 생성기를 계속 사용한다. `AI_GENERATION_ENGINE=staged`로 바꾸면 새 최초/추가 생성이 기존 생성기를 사용한다. 진행 중인 pi 작업의 엔진은 바뀌지 않는다.

## 실행 구조

- 동일한 생성 API, 권한 검사, 서버 동시 한도와 pg-boss를 사용한다. pi 작업은 기존 4단계 호출을 실행하지 않는다.
- pi SDK 1.4.0을 서버 내부에 넣는다. 개인 pi 설정, 로그인, 스킬, 셸과 파일 시스템 도구를 자동으로 불러오지 않는다. 선택 업로드와 프로젝트 기준 문서에 접근하는 도구만 제공한다.
- 에이전트는 화면 목록, 원문 문서의 범위 읽기와 검색, 이미지 확인, 기준 시트 검색, 기존 케이스 조회, 근거 규칙 등록, 선택값별 행 확장, 초안 저장·수정·삭제, 누락 검사, 제출 도구를 반복한다. 임의 셸/코드 실행은 제공하지 않는다.
- 기존 `sheet-v3` 분해 규칙을 주입하지 않는다. 기준 문서의 실제 예시를 읽고 작성하되 열 UUID, 형식, 선택값, QA 기록 보호는 서버가 검증한다.
- Figma 파일 전체나 선택 밖의 자료를 실시간 조회하지 않는다. 선택해 업로드한 화면 문서와 이미지 사본을 재조회한다. 선택 범위에 없는 설명은 추가 선택하거나 생성 메모로 보충해야 한다.
- SDK 대화 기록과 초안은 `generation_steps.output`에 체크포인트로 저장한다. 완료된 도구 묶음 이후 기록을 이어 쓰고, 초안의 같은 key 저장은 수정으로 처리한다. 완료 초안이 있으면 모델 재호출 없이 결과 저장을 재개한다.
- 생성 도중 서버 종료는 실패로 확정하지 않는다. 예산/모델 오류로 전체 검토를 마치지 못해도 작성된 케이스가 있으면 이를 저장하고 미완료 범위를 확인 필요로 남긴다. 초안이 전혀 없으면 작업을 실패 처리한다.
- 작업 종료 후 업로드와 단계 입력/출력을 삭제하는 기존 정책을 유지한다. 규칙·짧은 원문 근거·읽기 범위·케이스 해시·삭제 이유·부분 완료 여부는 `generation_steps.required_coverage`에 남는다. 프로젝트 기준 QA 문서는 이후 생성에 필요하므로 교체/연결 해제/프로젝트 삭제 전까지 DB에 보관한다.
- 토큰 상한은 관측한 누적 사용량을 기준으로 다음 대화 호출을 막는다. 호출 하나가 상한을 넘을 수 있으므로 정확한 금액 상한은 아니다. 실행 제한은 재시도해도 초기화하지 않는다. 누적 토큰/턴의 75%부터 마무리를 우선하도록 안내한다. 모델·요약 호출의 원시 사용량, 응답 ID, 실제 시간은 기존 사용량 테이블에 같은 호출 UUID로 남긴다. 캐시 쓰기와 추론 토큰을 구분하며 비용은 확인한 서비스 등급과 모델 단가로 산출한다. 청구서상의 실제 결제 금액과는 구분한다.

## Vercel과 Render

웹은 Vercel, API와 pi 실행은 Render의 Node 서버에서 동작하도록 설계한다. 웹 요청 연결과 생성 작업의 수명은 분리되어 있다. DB와 작업 체크포인트는 PostgreSQL에 둔다.

현재 저장소 구현은 `LocalStorage`이고 워커가 API 프로세스 안에서 실행된다. 같은 형태로 Render에 올릴 때는 업로드용 영속 디스크가 필요하다. **API와 Background Worker를 서로 다른 서비스로 분리하려면** 공유 객체 저장소 어댑터와 별도 워커 진입점을 먼저 추가해야 한다. Render의 서로 다른 서비스가 로컬 디스크를 공유한다고 가정하지 않는다. 이번 작업은 배포 설정이나 저장소 전환을 수행하지 않는다.

## 품질 비교

같은 프레임 사본, 생성 메모, 열 양식, 기준 문서로 비교한다. 참고 세션의 전체 4개 메뉴 결과와 일부 화면 결과의 개수를 직접 비교하지 않는다.

검토 항목은 유효한 검증 항목 수, 주요 조건·분기 누락, 근거 없는 예상 결과, 수행 가능성, 반복·중복, 기준 QA 문서와의 작성 방식 일치도다. 모델·시간·토큰과 부분 완료 여부도 함께 본다. 도구 검증 통과나 요구사항 연결 개수는 내용 품질을 보증하지 않는다.


## 보완 실험의 완료 기준

- `read_frame`의 `nextOffset`이 남아 있으면 이어 읽어야 한다. 첫 조각이나 검색만으로 전체 프레임을 읽었다고 처리하지 않는다.
- `save_requirements`에 각 화면의 원문 노드와 정확한 인용문을 등록하고 규칙의 확정 여부를 구분한다. 등록하지 않은 원문 규칙까지 서버가 의미적으로 발견하는 것은 아니므로 별도 검토가 필요하다.
- 모든 확정 선택값은 `covers`가 연결된 테스트 행이 있어야 한다. 불확실 규칙은 질문과 근거를 가진 확인 필요 항목으로 남긴다. 공통 열을 재사용하는 `save_case_variants`도 개별 행의 필수 열·연결을 검증한다.
- `check_coverage`의 누락만 보완하며 완료 직전 동일 검사를 다시 한다. 전체 완료와 부분 완료는 감사 기록으로 구분한다. 화면 상태와 사용자 문구는 이번 작업에서 바꾸지 않았다.
- 동일 8프레임 비교에서는 이전 pi와 같은 상한(2,000,000 토큰·80턴·1,500초)을 명시적으로 설정한다. 로컬 기본 상한은 1,000,000 토큰·1,200초이며 자동으로 높이지 않는다.
