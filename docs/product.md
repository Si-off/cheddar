# 제품 정의

이 문서는 합의된 제품 목적, 사용자 작업, 지원 범위와 제약을 설명한다. 개별 작업의 계획·시안·완료 보고만으로 제품 계약을 바꾸지 않는다. 현재 구현은 코드·실행 환경으로 확인하고 계약과 다르면 그 차이를 명시한다.

## 제품 목적과 범위

Cheddar는 사람이 수행하는 QA 테스트 케이스를 AI로 생성하고, 편집·공유·XLSX 내보내기 할 수 있는 제품이다.

- 단위 테스트 케이스: 개별 화면·기능을 대상으로 사람이 수행하는 QA 케이스.
- 통합 테스트 케이스: 여러 화면에 걸친 사용자 흐름을 대상으로 사람이 수행하는 QA 케이스.

이 구분은 제품 안에서 작성하는 QA 케이스의 범위를 뜻한다. 프로젝트 코드의 단위·통합 테스트 도구 선택을 의미하지 않는다.

## 구성요소별 역할

| 구성요소 | 확정된 역할 |
| --- | --- |
| Figma 플러그인 | 선택한 Figma 프레임의 데이터·이미지 업로드에 집중 |
| 웹 | AI 테스트 케이스 생성·편집, 공유와 XLSX 내보내기 제공 |
| 백엔드 서버 | 프로젝트·파일·업로드·시트·IA·기본 양식 저장과 XLSX 제공. Haiku·Luna AI 생성 작업과 후보 저장 |

## 편집과 공유

- 편집 UI는 전체 테스트를 한눈에 볼 수 있는 표를 기본으로 구성한다. 보기 설정 드롭다운 안에서 표·QA 진행 목록을 전환한다. 추가 행동은 메뉴·모달·상세 시트에서 제공한다. 셀은 긴 텍스트를 줄바꿈하며 내용에 따라 행 높이가 늘어난다. 표 안에서 편집하거나 상세 패널을 사용할 수 있으며, 좁은 화면에서는 표 내부를 가로 스크롤한다.
- 팀·개인별 작성 방식에 대응하는 구성 자유도와 인터랙션을 지향한다. 열 추가, 열 이름 정의, 열 순서 변경, 열 너비 조절, 일반 문자열 검색 기능을 포함한다.
- 사용자 정의 열은 텍스트부터 지원한다. 검색은 표시 문자열 전체의 대소문자 구분 없는 부분 일치다. 후보는 별도 목록이다.
- 공유는 후속 단계의 링크 열람 기능이며, 도입 시 초기 링크는 읽기 전용이다.
- 링크별 편집 권한 지원은 향후 범위다.

## 초기 검증 환경

- 로그인과 검색 노출 없이 개발자 PC에서 로컬 검증한다.
- 백엔드와 DB도 로컬에서 실행한다.
- 사내 배포는 추후 결정한다. 로컬 링크 열람의 구체적인 접근 범위와 연결 방식은 미정이다.

## 승인된 업무 모델과 단계 경계

아래는 제품 계약이며 개별 체크아웃의 구현 상태와 구분한다. 화면 개편에도 기존 백엔드·저장 기능을 유지하며 시안의 모킹 데이터와 메모리 전용 저장 방식을 제품에 적용하지 않는다. 결정과 변경 이력은 [1단계 설계](changes/2026-10-15-stage-1-foundation/design.md)와 [화면 개편 기록](changes/2026-10-16-workspace-redesign/change.md)에 있다.

- 프로젝트는 기본 양식·IA·업로드 묶음·시트를 묶는다. 프로젝트 이름은 1~100자이며 중복을 허용한다.
- 플러그인은 프로젝트를 선택하고 프레임 데이터·이미지를 하나의 업로드 묶음으로 등록한다. 직접 Frame 선택과 Section 선택을 지원하며, Section에서는 내부의 최상위 Frame들을 수집한다. 수집한 Frame 내부의 중첩 프레임은 별도 업로드 항목으로 추가하지 않고 중복 선택은 한 번만 포함한다. 업로드 전 표시된 프레임 목록을 확인한다. 초기 업로드 교체·버전 관리는 제외한다.
- 새 시트는 프로젝트 기본 양식의 사본을 사용한다. 기존 시트는 기본 양식 변경의 영향을 받지 않는다. 업로드 없이 빈 시트도 만들 수 있다.
- 케이스는 생성 전부터 편집 가능하다. 새 프로젝트 기본 표시 항목은 테스트 ID·기능 구분·테스트 항목·화면 ID·사전 조건·테스트 데이터·수행 절차·예상 결과다. 기능 구분·테스트 데이터는 기본 양식의 사용자 정의 텍스트 열이며 이름·순서·값을 편집할 수 있다. 우선순위·관련 화면 시스템 필드는 추가 설정에 유지한다. 기존 프로젝트 양식·시트와 사용자가 정한 열 이름은 변경하지 않는다. 내부 UUID와 표시용 테스트 ID는 별개다.
- 수행 단계와 기대 결과는 긴 문자열이다. 우선순위는 높음·보통·낮음 또는 미지정이다. 빈 초안 저장을 허용한다.
- 시스템 열은 이름·순서·너비를 변경하고 사용자 정의 열은 추가·수정·삭제한다. 시스템 열 삭제는 초기 제외한다. 사용자 열 삭제 시 해당 값도 제거한다.
- 자동 저장은 미저장 입력을 보존하며 수정 충돌을 덮어쓰지 않는다. 표의 복붙·키보드·상세 패널 편집을 지원한다. 저장되지 않은 채 이동할 때는 로컬 초안 보관 성공을 확인하고 사용자가 이동을 선택한다. 서버와 로컬 보관이 모두 실패하면 입력을 유지하고 이동을 막는다.
- IA 화면 ID는 프로젝트 내에서 유일하고 대소문자를 구분한다. Figma node ID와 별개다. 내부 UUID로 연결하므로 화면 ID 이름이 바뀌어도 연결을 유지한다. 참조 중인 항목은 연결 해제 후 삭제한다.
- IA는 수작업 및 XLSX·CSV 분석 결과 검토·수정·확정으로 등록한다. AI가 화면 연결을 확신하지 못하면 비워둘 수 있으며 그 이유만으로 후보로 보내지 않는다.
- 플로우차트는 시트별이며 의미·IA 연결과 위치·확대율을 분리한다. 시작·종료·화면·행동·조건 분기와 방향·조건 연결을 지원한다. 이미지/Figma 프레임 분석 결과는 검토 후 사용한다. 플로우 없이도 통합 생성할 수 있다.
- AI는 실행마다 Claude/OpenAI를 선택한다. 프레임·IA·선택 설명·플로우·시트 양식·기존 예시를 입력으로 사용하며 사용자가 목표 개수를 정하지 않는다. 웹에서는 생성 결과 검토 후 선택한 케이스를 기존 시트에 추가한다. 기존 교체 API는 호환을 위해 유지한다.
- 근거가 명확한 결과는 케이스, 추론·모호한 결과는 이유를 포함한 후보로 분리한다. 후보의 검토 대기·추가됨·제외됨을 저장하고 제외 항목 다시 보기를 지원한다.
- 생성 중 대상 시트만 잠근다. 결과가 정상 준비된 뒤 교체하고 실패 시 기존 내용을 보존한다. MVP LangGraph는 입력 준비 → 생성 → 형식·참조 검사 → 저장 순서다. 자동 재시도와 분할 생성은 제외한다. 생성 상태는 다시 조회할 수 있고, 서버 중단으로 끝내지 못한 작업은 10분 후 실패로 표시한다.
- XLSX는 저장된 현재 시트 전체 케이스를 현재 열 이름·순서로 내보낸다. 검색 필터와 후보는 포함하지 않는다.
- 초기 기준 규모는 업로드 묶음 약 20프레임, 시트 약 500케이스다. 검증된 성능이나 생성 목표·개수 제한을 뜻하지 않는다.

MVP 범위는 프로젝트·파일·업로드 묶음·시트·수작업 IA·기본 양식·XLSX와 아래 AI 생성·후보 검토다. 새 시트를 먼저 만든 뒤 생성하거나 기존 시트 교체를 확인하고 생성한다. IA 파일 분석·플로우차트·실제 공유 링크는 후속 범위다. 구현·검증 이력과 당시 미확인 사항은 [시트 편집](changes/2026-10-15-stage-2b-sheet-editor/change.md), [프로젝트 설정](changes/2026-10-15-stage-2c-project-settings/change.md), [프레임 업로드](changes/2026-10-15-stage-2a-frame-upload/change.md), [AI 생성](changes/2026-10-15-mvp-generation/change.md) 기록에 있다. 실제 모델 권한·응답 품질과 실행 환경은 별도로 확인한다.

## 갱신 기준

사용자가 결정한 내용을 반영하고, 관련 작업이나 결정 기록이 있으면 연결한다. 제안과 미해결 질문은 확정 항목에 섞지 않는다. 기존 결정을 바꾸면 현재 내용과 결정 근거를 함께 갱신한다.

## MVP AI 입력과 실행

Claude Haiku 또는 OpenAI Luna를 실행마다 선택한다. 선택한 업로드의 PNG·노드 JSON, 프로젝트 IA, 시트 양식·기존 케이스와 설명을 해당 서비스에 전송한다. 업로드 없이 설명만으로 생성할 수도 있다. 플로우 입력은 후속이다. API 키는 서버 환경변수로만 관리한다. 전체 입력 파일 20 MiB 또는 구성한 텍스트 350,000자를 초과하면 데이터를 잘라내지 않고 오류로 알린다. 각 모델 호출은 최대 4분이며 출력 토큰 한도에 도달한 응답은 기존 시트에 반영하지 않는다.

AI 입력의 노드 JSON은 원본 저장 파일과 분리해 변환한다. 전체 노드·텍스트·부모 관계·컴포넌트 상태·전환 정보를 유지하고 반복 문자열과 동일 상태는 참조 표로 표현한다. 스타일·벡터 등 렌더링 메타데이터는 텍스트 입력에서 제외하고 프레임 PNG를 함께 전달한다. 크기 제한은 이 변환 후 입력에 적용한다.

## 화면 흐름과 시트 열람

프로젝트 목록 → 시트 목록 → 표 편집으로 화면 깊이를 분리한다. 생성·후보 검토·공유 시트 미리보기는 시트 메뉴에서 열고, 상세 편집은 옆에서 여는 시트로 제공한다. 너비·높이는 표 경계선에서 조절한다. 현재 보기 전환·열 숨김·행 높이는 열려 있는 편집 화면에서 유지되는 표시 설정이며 서버 업무 데이터와 분리된다. QA 보기는 전체 목록에서 수행 내용을 펼쳐 확인하고 기존 편집으로 연결하며 별도 QA 결과 저장 모델을 추가하지 않는다. 공유 시트 미리보기는 현재 시트를 읽기 전용으로 열람하며 Figma 화면 미리보기를 포함하지 않는다. 실제 공유 링크 발급·외부 열람은 후속 결정 범위다.

## QA 작성과 근거 검토

- 웹 생성은 업로드의 개별 프레임을 선택하고 결과 검토 모드로 실행한다. 기존 시트는 유지하며 근거가 있는 생성 케이스와 검토 후보를 나눠 저장한다. 수정 저장 후 선택한 항목을 한 번에 추가한다. 유사 케이스 비교는 제목 단어의 겹침에 따른 탐색 보조이며 중복 판정이나 AI 신뢰도를 뜻하지 않는다.
- 처음 사용하는 프레임은 AI가 화면, 상태, 원문 요구사항과 관계를 정리한 다음 케이스를 생성한다. 원문과 이미지의 원본 영역은 보존한다. 이미 저장된 정리와 사용자 수정이 있으면 이를 우선 사용한다. 사전 수작업 연결은 요구하지 않는다.
- 생성 이후 편집기의 작은 근거 수정 버튼에서 자료, 정책, 요구사항을 같은 화면의 모달로 수정한다. 요구사항과 관계의 제목, 유형, 화면 연결과 원본 영역을 수정할 수 있다. 원본 업로드 파일은 수정하지 않는다.
- 후보의 확인 사유는 정책 항목으로 저장된다. 답변은 기본적으로 해당 후보 보완에 사용하며 프로젝트 규칙 저장을 선택할 때 이후 생성의 공통 정책으로 사용한다. 미답변 정책의 동작을 확정하지 않는다.
- 요구사항과 시트 케이스의 연결을 저장한다. 연결 누락 필터는 현재 시트의 실제 연결 유무를 나타내며 테스트 누락이나 테스트 품질의 자동 확정으로 해석하지 않는다.
- 원본 대조 패널은 선택한 케이스의 관련 이미지를 확대해 보고 근거 문장의 원본 영역을 확인한다. 좁은 화면에서는 같은 화면의 겹침 패널로 표시한다.
- 자료 정리와 케이스 생성은 검토 모드에서 최대 두 번의 AI 호출이다. 전체 작업 제한은 8분이고 중단 작업의 실패 판정은 기존 10분을 유지한다. 실제 모델 품질과 범용 문서 분리 정확도는 별도 검증한다.
