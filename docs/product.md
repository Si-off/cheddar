# 제품 정의

이 문서는 합의된 제품 목적, 사용자 작업, 지원 범위와 제약을 설명한다. 시안이나 작업 보고만으로 제품 계약을 바꾸지 않는다. 현재 구현은 코드로 확인하고 계약과 다르면 그 차이를 명시한다.

2026-10-18 전면 개편으로 이 문서를 새로 썼고, 2026-10-19에 코드가 이 문서를 따르도록 개편을 마쳤다. 2026-10-21에 시트 개선안(양식 고정과 열 선택, 화면 ID 규칙, 표 편집)을 확정해 이 문서에 반영했다. 이 개선안은 아직 코드에 반영하지 않았으며, 구현 범위는 [프로젝트 구조](architecture.md)의 "시트 개선안" 절에 있다.

## pi 생성

최초/추가 생성의 기본 엔진은 pi이며, 기본 모델은 Claude Sonnet 5.5·medium이다. 프로젝트 양식과 한 번 등록한 기준 QA 문서로 선택 프레임의 테스트 시나리오를 작성한다. 기준 문서 등록은 운영자 CLI로 제공하며 웹 등록 화면은 아직 없다. 기준 문서가 없으면 기존 작성 예시를 참고한다. 다시 작성과 열 채우기는 기존 생성기를 쓴다. 사용법은 [pi 생성](pi-experiment.md)을 따른다.

이전 pi의 원문 확인 → 초안 작성 → 대조·수정 방식을 사용한다. 선택값별 행 분할이나 근거 규칙 등록을 강제하지 않는다. 부분 결과가 있으면 작성한 케이스를 보존하고 검토하지 못한 범위를 확인 필요에 남긴다.

서로 다른 테스트 세트의 생성 요청은 대기열에 접수한다. 기본 2건을 실행하고 나머지는 기다린다. 기다리는 시간 때문에 작업이나 사용 중인 업로드를 만료시키지 않는다. 같은 세트에서는 진행 중인 작업 하나를 유지하며 같은 요청의 재전송은 기존 작업을 반환한다. 이는 동일 결과의 중복 저장과 양식 충돌을 막기 위한 기존 규칙이다.

## 기능 명칭

- **프로젝트**: 테스트 세트를 만들 때 쓰는 설정 묶음. 양식, 기능 그룹, 화면 구조(화면 ID 규칙 포함), 메모를 가진다.
- **테스트 세트**: 배포마다 만드는 QA 테스트 케이스 묶음. 코드 이름은 `test-set`이다. 표와 캔버스는 테스트 세트를 보는 방식(보기)이며 이름에 넣지 않는다.
- **테스트 케이스**(줄여서 케이스): 테스트 세트 안의 한 행. 사람이 수행하는 QA 확인 하나.
- **확인 필요**: AI가 생성 중 예상 결과를 하나로 정할 수 없어 사람의 답이 필요한 항목.
- **기능 그룹**: 케이스를 나누는 작은 도메인 단위(예: 주문 조회, 주문 취소). 케이스마다 자기 기능 그룹을 저장하며 표와 XLSX에는 열로 나오지 않는다.
- **양식**: 테스트 세트의 열 구성. 열은 사전 정의 열과 사용자 열로 나뉜다.
- **사전 정의 열**: 제품이 현업 QA 시트를 분석해 이름, 형식, 작성 기준을 미리 정한 열. 사용자는 켜고 끄기만 한다.
- **사용자 열**: 사용자가 이름, 형식, 작성 기준을 직접 정하는 열.
- **작성 기준**: 열마다 붙는 작성 규칙. AI가 그 열을 채울 때 따른다.
- **화면 ID 규칙**: 화면 ID를 어떤 부분으로 조합하는지 정한 규칙(예: `PC_CPN_REG_PG_001`). 프로젝트마다 여러 개 둘 수 있다.
- **점검 관점**: 생성할 때 빠지면 안 되는 QA 확인의 종류. 제품 내부 로직이며 화면에 노출하지 않는다.
- **보기**: 같은 케이스를 보여주는 방식. 표 보기와 캔버스 보기가 있다.
- **그룹화**: 캔버스에서 케이스를 나누는 기준. 기능 그룹(기본), 선택·태그·체크박스 항목 값, 없음 중에서 고른다.

단위 테스트와 통합 테스트라는 분류와 개념은 쓰지 않는다. 화면, 데이터, 생성 어디에도 이 구분을 두지 않는다.

## 제품 목적과 범위

Cheddar는 사람이 수행하는 QA 테스트 케이스를 Figma 기획 자료로부터 AI로 만들고, 여러 사람이 함께 편집하고, 공유하고, XLSX로 내보내는 사내 도구다. 외부 협력사 개발자는 공개 링크로 보거나 편집한다.

사용자는 Figma 섹션을 통째로 올리고 메모를 짧게 쓰거나 아예 쓰지 않는다고 가정한다. 그래도 그대로 QA에 쓸 수 있는 테스트 세트가 나와야 한다.

## 프로젝트

- 프로젝트는 설정 묶음이다. 테스트 세트를 프로젝트별로 묶어 보여주지 않는다.
- 모든 계정이 모든 프로젝트를 보고 만들고 설정을 바꾼다.
- 만들 때 이름(필수)과 설명을 쓴다. 사전 정의 열 14개가 켜진 상태로 함께 만들어진다.
- 사전 정의 열은 현업 QA 시트의 열 순서를 따른다: 테스트 ID, 테스트 환경, 테스트 케이스, 제목, 사용자/관리자, 화면 ID 또는 URL, 수행 절차, 예상 결과, QA 결과, QA 담당자, 결과 및 의견, 개발 진행 상태, 개발 담당자, 추가 정보. 원본의 Case ID는 테스트 ID, Task는 제목, Test Case는 테스트 케이스에 대응한다. 릴리즈 범위와 개별 시나리오 내용은 열에 넣지 않는다.
- 사전 정의 열은 두 묶음이다. AI 작성 열(테스트 ID부터 예상 결과까지)은 Figma 자료에서 채우고, QA 기록 열(QA 결과부터 추가 정보까지)은 비워서 만들고 사람이 채운다. 추가 정보는 기본으로 꺼져 있다.
- 사용자/관리자는 사용자와 관리자 중 선택한다. QA 결과는 Pass, Fail, Deferred, N/A, -, 추가 요청을, 개발 진행 상태는 완료, 수정중, 수정 완료, 보류, 기타, -를 선택값으로 쓴다. 나머지는 텍스트다.
- 사전 정의 열의 화면 설명은 열 이름만으로 뜻이 드러나지 않을 때만 짧은 명사구로 둔다(테스트 케이스: "시나리오 이름", 제목: "테스트 케이스 안의 하위 시나리오 이름"). 나머지 사전 정의 열은 설명이 없다. AI 작성 규칙은 내부 로직이라 화면에 보이지 않고 작성 지침의 열 규칙에 둔다(2026-10-26 결정). 규칙은 9/16, 9/18, 9/30 QA 시트의 실제 값으로 정했고 시나리오 열만 다룬다. 릴리즈 범위와 날짜는 열에 넣지 않는다. 테스트 환경은 APP, WEB, ADMIN, PC/mo-web처럼 쓰고 iOS와 AOS는 나누지 않는다. 테스트 케이스는 화면과 기능을 쓰고 수행 경로가 갈리면 다음 줄에 `Case 1. 정상 등록`처럼 붙인다. 제목은 하위 시나리오 명사구나 `Case 2-1. 이미 등록된 쿠폰`처럼 조건을 쓴다. 사용자/관리자는 수행하는 쪽만 고르고 회원 여부 같은 상태는 제목의 Case 조건으로 쓴다. 화면 ID는 화면 구조나 화면에 적힌 ID를 쓰고 여러 화면이면 줄마다 쓰며, 아직 없으면 "추후 채번", 대상 화면이 없으면 "-"다. 수행 절차는 번호 목록이고 버튼은 `[등록하기]`로 감싸며 같은 테스트 케이스 안에서 번호를 이어 쓴다. 예상 결과는 `- …되는지 확인`을 줄마다 쓰고 문구와 버튼은 `문구 : `, `버튼 : ` 뒤에 원문 그대로 적으며, 테스트 데이터를 만드는 행은 "테스트 전 준비사항"이다. 같은 묶음의 행은 같은 값을 써서 표와 XLSX가 병합으로 그린다. QA 기록 열은 생성 시 비운다.
- 프로젝트 설정 탭: 양식, 기능 그룹, 화면 구조, 메모.
- 양식: 새 테스트 세트의 기본 열을 정한다. 사전 정의 열은 이름, 형식, 작성 기준을 바꿀 수 없고 켜고 끄기만 한다. 테스트 ID와 제목은 항상 켜져 있다. 사용자 열은 이름, 형식(텍스트, 선택, 체크박스, 태그), 작성 기준을 직접 정해 추가하고 편집하고 삭제한다. 선택과 태그의 값 목록은 미리 정하며 AI는 그 목록에서만 고른다. 작성 기준은 AI가 그 열을 채울 때 따르는 설명이며, 자료에 근거가 없으면 비워 두게 한다.
- 기능 그룹: 추가, 이름 변경, 설명 편집, 순서 변경, 삭제. AI는 이 목록에 맞춰 케이스를 나누고 맞는 그룹이 없을 때만 새 그룹을 제안한다.
- 화면 구조: 화면 ID, 이름, 유형(페이지, 팝업, 바텀시트, 탭), 상위 화면, 설명. 화면 ID는 프로젝트 안에서 유일하다. 모듈별로 묶어 보여준다. "가져오기"로 이미 만든 화면 목록 자료(XLSX, CSV, 텍스트, 붙여 넣은 글, PNG/JPG 이미지)를 넣으면 AI가 화면을 찾고, 사용자가 모듈별로 고른 화면만 추가한다(2026-10-23 결정). 엑셀은 AI가 화면 ID, 경로(module, Depth), 유형, 설명 열만 정하고 행은 서버가 펼친다. 비어 있는 상위 경로는 윗행 값을 잇고, 버튼처럼 화면이 아닌 유형은 뺀다. ID가 없는 화면은 빼고 개수만 알리며, 같은 ID가 여러 행이면 첫 행만 쓴다. 프로젝트에 이미 있는 ID는 "있음"으로 보여 고를 수 없고 덮어쓰지 않는다. 고르지 않은 상위 화면은 건너뛰고 그 위 화면에 잇는다. 읽지 못한 파일이 있어도 멈추지 않고 그 파일 이름만 알린다.
- 화면 ID 규칙: 화면 구조 탭 안에서 다룬다. 프로젝트에 규칙을 여러 개 둘 수 있다(예: 관리자 화면 `PC_CPN_REG_PG_001`, 앱 화면 `U_SP_0103_ES_PG_010`). 규칙은 예시 ID를 부분으로 나눈 것이며, 부분마다 이름과 종류(코드 목록, 고정값, 번호)를 정한다. 코드 목록은 코드와 뜻의 쌍이고, 번호는 자릿수를 정하며 앞 부분이 같은 화면끼리 이어서 센다. 부분은 추가, 이름 변경, 종류 변경, 삭제, 끌어서 순서 변경을 한다.
- 규칙 추가는 먼저 자료 넣기 창을 연다. 자료를 넣고 "규칙 만들기"를 누르면 AI가 자료의 화면 ID에서 규칙 초안을 만들고, 사용자는 찾은 규칙을 고르고 편집기에서 고친 뒤 추가한다. "직접 만들기"는 빈 편집기로 간다. 초안의 코드는 자료에 나온 값만 쓰고 뜻은 자료에서 알 수 있을 때만 채운다. 몇 개 ID에만 맞는 예외 구조는 규칙으로 만들지 않아 그 ID는 "규칙 불일치"로 남는다(2026-10-23 결정).
- 규칙이 있으면 화면을 추가할 때 다음 ID를 제안하고, 규칙에 맞지 않는 ID에 "규칙 불일치"를 표시한다. 규칙을 지워도 화면 ID는 그대로 남는다. 규칙 삭제는 확인 대화상자를 거친다. AI는 규칙으로 ID를 지어내지 않는다.
- 메모: 프로젝트마다 하나인 자유 글. 입력을 멈추면 저장한다. AI에 전달하지 않는다.
- 점검 관점은 설정 화면에 없다. 프로젝트 규칙, 화면 분석, 유사 케이스 비교도 없다.

## 테스트 세트와 케이스

- 테스트 세트는 최상위 목록에만 보인다. 목록 필터는 전체와 내가 만든 테스트 세트이고 만든 사람과 공개 링크 여부를 표시한다.
- 만들 때 이름과 프로젝트를 고르고, 프로젝트는 이후 바꾸지 않는다. 양식과 기능 그룹, 화면 구조가 그 프로젝트를 따르기 때문이다.
- 새 테스트 세트: 이름, 프로젝트, 양식, Figma 프레임을 정한다. 양식은 프로젝트 기본 양식, 최근 테스트 세트와 같게, 직접 고르기 중 하나다. 앞의 둘은 열 이름을 미리 보여준다. 직접 고르기는 모달에서 표 머리글 모양으로 열을 켜고 끄고 끌어서 순서를 바꾸며 사용자 열을 더한다. 프레임은 플러그인이 올린 것이 모두 선택된 상태에서 눌러 해제한다.
- 새 테스트 세트에서 "직접 작성"을 고르면 케이스 없이 만들고 바로 연다. 생성으로 만드는 흐름은 AI 생성 절을 따른다.
- 모든 계정이 보고 편집하고 내보낸다. 삭제는 만든 사람과 관리자만 한다. 계정이 없는 사람은 공유 절의 공개 링크를 따른다.
- 새 테스트 세트는 고른 양식의 사본을 쓴다. 이후 프로젝트 양식이 바뀌어도 영향을 받지 않는다. 테스트 세트 안에서 열을 더하고 빼고 순서를 바꿀 수 있다.
- 케이스와 프레임, 요구사항, 화면 구조의 연결(근거)은 저장하지 않는다.
- 표 보기: 행과 열 편집, 복사와 붙여넣기, 키보드 이동, 표 안의 세로선과 가로선과 교차점을 끌어 크기 조절. 셀을 고른 뒤 Enter, 두 번 누르기, 글자 입력으로 고치고 Delete로 비운다. 고친 값은 Enter뿐 아니라 다른 셀이나 표 밖을 눌러도 반영되고, Esc만 취소한다. 붙여넣기는 탭으로 나뉜 글자를 고른 셀부터 채운다. 선택과 태그 열에도 목록에 없는 값을 붙여넣거나 직접 쳐서 넣을 수 있다(Google 스프레드시트 기본 동작). 체크박스 열만 참과 거짓으로 읽을 수 없는 값을 건너뛴다. 표는 묶지 않고 한 장으로 보인다. 표는 화면 높이를 채우고 표 안에서 위아래와 좌우로 스크롤한다.
- 표 편집 기능의 이름, 동작, 단축키는 Google 스프레드시트를 따른다. 단축키는 Mac(⌘)과 Windows(Ctrl) 모두 Sheets와 같고, 메뉴에는 사용자 OS에 맞는 표시를 보여준다. 폰트와 서식 기능은 두지 않는다.
- 셀 도구: 테스트 세트 도구 상자 안에 수정, 삽입, 셀 병합 메뉴를 아이콘으로 두고 메뉴 맨 위에 그룹 이름을 보인다. 스프레드시트 메뉴 막대처럼 메뉴 하나를 연 뒤 같은 도구 상자의 다른 메뉴 아이콘에 포인터를 올리면 그 메뉴로 바뀐다. 고른 셀이 없거나 쓸 수 없는 항목은 흐리게 둔다. 막대 맨 앞에 실행취소(⌘Z, Ctrl+Z)와 재실행(⌘Y, Ctrl+Y)을 둔다. 수정: 잘라내기, 복사, 붙여넣기, 아래로 채우기(⌘D), 행 위로 이동, 행 아래로 이동, 값 삭제, 행 삭제, 찾기 및 바꾸기(⇧⌘H, Ctrl+H). 삽입: 위에 행 1개 삽입(⌘⌥=, Ctrl+Alt+=), 아래에 행 1개 삽입, 드롭다운, 셀 안에 이미지. 행 삭제는 ⌘⌥-, Ctrl+Alt+-. 단축키는 Google 스프레드시트 도움말의 단축키 목록과 같다(재실행은 ⇧⌘Z, Ctrl+Shift+Z도 받는다). 셀 병합: 세로로 병합, 병합 취소. 셀 우클릭 메뉴는 잘라내기, 복사, 붙여넣기, 행 삽입, 값 삭제, 행 삭제, 병합 취소를 같은 이름과 단축키로 둔다.
- 범위 선택: Shift+클릭, Shift+방향키, 끌기로 사각형 범위를 고른다. 복사와 잘라내기는 범위를 스프레드시트 형식(탭과 줄바꿈, 여러 줄 셀은 따옴표)으로 옮기고, 붙여넣기는 범위의 왼쪽 위부터 채운다. 값 삭제와 Delete는 범위를 비우고 행 삭제는 범위의 행을 지운다. 아래로 채우기는 범위 첫 행 값으로 나머지 행을 채우고, 한 행만 골랐으면 바로 위 행 값을 가져온다. 행 이동은 범위의 행을 함께 옮기며 테스트 ID는 케이스를 따라간다. 세로로 병합은 병합 표시 열 하나의 여러 행을 맨 위 값으로 맞추며, 값이 다른 셀이 있으면 스프레드시트처럼 맨 위 값만 남는다고 먼저 묻는다. 범위를 고르면 화면 읽기 프로그램에 고른 행과 열 수를 알린다. 링크 방문자는 행을 옮기지 못한다.
- 실행취소와 재실행: 내가 한 셀 편집과 행 추가, 삭제, 이동만 기록한다(열 추가와 삭제는 기록하지 않는다). 지운 행은 같은 테스트 ID로 원래 자리에 되살린다. 되돌릴 셀을 그 사이 다른 사람이 바꿨으면 그 셀은 건너뛰고 "다른 사람이 바꾼 셀은 되돌리지 않았습니다"를 알린다(2026-10-22 결정).
- 찾기 및 바꾸기: 대화상자에서 찾기, 바꾸기, 대소문자 구분, 전체 셀 내용 일치를 고른다. 찾기는 고른 셀 다음 셀로 옮겨 가고, 바꾸기는 고른 셀을 바꾼 뒤 다음으로 가며, 모두 바꾸기는 바꾼 셀 수를 알린다. 체크박스 열과 테스트 ID는 대상이 아니다.
- 셀 편집은 같은 셀이면 나중 값이 이긴다. 저장에 실패하면 알리고 서버의 내용으로 되돌린다.
- 열 추가: 머리글 끝의 `+`에서 양식에서 뺀 사전 정의 열을 되돌리거나 사용자 열을 직접 정의한다. 열을 더할 때 "기존 케이스 N개 AI로 채우기"를 켜면 기존 케이스를 대상으로 그 열만 AI가 작성한다(값이 있는 셀은 두고 확인 필요는 만들지 않는다). 기본은 꺼짐이다. 테스트 환경 열은 환경에 따라 동작이 다른 케이스만 환경별 행으로 나누고 나머지는 "공통"이다.
- 열 머리글 메뉴: 이름 변경, 작성 기준 편집, 선택 항목 편집(선택과 태그 형식), 왼쪽·오른쪽에 열 추가, 열 삭제. 사전 정의 열은 이름 변경, 작성 기준 편집, 선택 항목 편집을 할 수 없다. 열을 지우면 그 열의 값이 함께 지워지므로 확인 대화상자를 거친다.
- 선택 셀: 값은 항목 색의 칩에 ▾를 붙여 보인다(Google 스프레드시트의 드롭다운 칩). 칩이나 빈 셀의 ▾를 한 번 누르면 값 목록이 셀 가운데 아래에 열리고, 목록의 항목도 같은 색 칩으로 보인다. Enter나 두 번 누르기도 같은 목록을 연다. 목록은 288px까지만 늘어나고 그 뒤로는 목록 안에서 스크롤한다. 사용자 열의 목록 아래에는 항목 편집 버튼을 고정해 두고, 누르면 같은 자리에서 목록이 편집 상태로 바뀐다. 편집 상태에서 항목 이름 고치기, 항목 앞 색 점으로 칩 색 고르기(회색, 빨강, 노랑, 초록, 청록, 파랑, 보라), 끌어서 순서 바꾸기, 호버 ×로 지우기, 항목 추가를 하고 완료(또는 Enter)로 저장하고 닫는다. Esc로 닫으면 바꾸지 않는다. 빈 항목과 같은 이름은 그 자리에서 막는다. 머리글 메뉴의 선택 항목 편집도 같은 편집 패널을 머리글 아래에 연다. 항목 편집은 열을 바꾸는 일이라 링크 방문자에게는 연필이 없다.
- 셀 비우기는 스프레드시트처럼 Delete 키나 값 삭제로 한다. 드롭다운에는 비우기 항목을 두지 않는다.
- 항목 색: 항목마다 칩 색을 둔다. 색을 정하지 않은 항목은 회색이다. 항목 이름을 고치면 색이 따라간다. 사전 정의 열은 항목처럼 색도 고칠 수 없고 기본 색을 쓴다(QA 결과의 Pass는 초록, Fail은 빨강 등).
- 드롭다운 만들기: 사용자 텍스트 열의 셀을 고르고 삽입 > 드롭다운을 누르면 그 열 전체가 선택 열이 된다(열 단위, 2026-10-22 결정). 열에 있던 글자 값이 처음 나온 순서대로 항목이 되고(항목 규칙을 넘는 값은 빼고 50개까지, 값이 없으면 "항목 1") 바로 그 셀 아래에서 항목 편집이 열린다. 글자 값은 그대로 남아 목록 밖 값 규칙을 따르고, 그 열의 이미지 셀은 비운다. 사전 정의 열은 형식이 AI 생성 규칙과 묶여 있어 바꿀 수 없다. 열 연산이라 실행취소로 되돌리지 않는다.
- 셀 안에 이미지: 텍스트 열의 셀을 고르고 삽입 > 셀 안에 이미지로 PNG, JPG, GIF, WebP 이미지(10MB 이하)를 넣는다. 셀 하나에 한 장이며 넣으면 글자 대신 이미지가 셀 값이 된다(Google 스프레드시트와 같다, 2026-10-22 결정). 셀에는 높이 96px의 썸네일로 보이고 Enter나 두 번 누르기로 크게 본다. 글자를 치면 글자로 바뀌고 Delete로 비운다. 공개 링크에서 편집할 수 있는 사람도 넣을 수 있다. 검색, 복사, 병합 판단, AI 생성은 이미지 셀을 빈 글자로 본다.
- 선택 항목을 고치거나 지워도 이미 입력된 셀 값은 바꾸지 않는다. 목록에 없는 값(직접 친 값, 붙여넣은 값, 항목을 바꿔 목록 밖이 된 값)이 든 셀은 칩 없이 글자로 보이고 오른쪽 위에 빨간 삼각 표시가 붙는다(Google 스프레드시트의 데이터 확인 경고와 같다). 안내 문구나 확인 대화상자는 없다. 그 셀을 Enter나 두 번 누르기로 열면 현재 목록에서 고른다. 목록 밖 값을 목록에 바로 추가하는 기능은 두지 않는다(2026-10-22 결정).
- 열 순서: 머리글을 끌어서 바꾼다. 테스트 ID는 맨 앞에 고정이고, 묶인 머리글(QA 진행, 개발 작업상황)은 묶음째 움직인다. 열 순서는 테스트 세트 전체에 저장하며 XLSX도 이 순서를 따른다. 바꾼 뒤 되돌리기 토스트를 보여준다.
- 병합 표시: 테스트 환경, 테스트 케이스, 제목, 화면 ID, 수행 절차에서 연속한 같은 값은 병합된 셀로 그린다. 테스트 환경과 테스트 케이스의 병합 경계는 그 뒤 열도 넘지 않고, 제목, 화면 ID, 수행 절차는 현업 시트처럼 같은 테스트 케이스 안에서 서로의 경계를 넘어 병합한다(2026-10-22 결정). 테스트 ID와 예상 결과는 병합하지 않는다. 값은 모든 행에 저장하므로 검색, 그룹화, 확인 필요는 영향을 받지 않는다. 병합된 셀을 고치면 묶음 전체에 반영되고, "병합 취소"는 병합만 풀어 값을 그대로 남긴다.
- 캔버스 보기: 행과 열이 길어 한눈에 보기 어려운 표 대신 시나리오를 읽기 쉽게 보여주는 사용자 중심 보기다(2026-10-22 결정, QA 전용 화면이 아니다). 그룹화 기준마다 세로 열을 두고 케이스를 카드로 놓는다. 기능 그룹으로 나누면 프로젝트 순서대로 열을 두고, 그룹이 없거나 지워진 그룹의 케이스는 맨 뒤 "미분류" 열에 모은다. 카드를 다른 열로 끌면 그 그룹(또는 항목 값)으로 옮긴다. 열의 +는 그 그룹에 케이스를 더한다.
- 캔버스 조작: ⌘(Ctrl)+휠이나 확대·축소 버튼으로 크기를 바꾸고, 휠이나 빈 곳 끌기로 움직인다. 확대율은 크기만 바꾸고 보이는 내용은 바꾸지 않는다. 비율을 누르면 100%로 돌아온다. 표시를 간략(테스트 ID와 제목)과 상세(모든 열을 이름 칸과 값 칸으로, 그 자리에서 편집)로 바꾼다. 간략 카드를 누르면 케이스 대화상자를 연다.
- 캔버스의 QA 결과 표시: 양식에 QA 결과 열이 있을 때만 켠다. 카드에 결과 색(Pass 초록, Fail 빨강, 그 밖의 기록 노랑, N/A와 - 회색)을 옅은 배경과 글자로 표시하고, 열 머리에 진행 수(기록한 수/전체, Fail 수)와 진행 막대를 둔다. 캔버스 왼쪽 아래 결과 요약(결과별 수, 미진행)을 누르면 그 결과의 카드만 또렷하게 남기고 나머지는 흐리게 한다. 카드 왼쪽 색 띠는 쓰지 않는다.
- 캔버스 도구: 도구 상자의 보기별 도구 자리에 실행취소, 재실행, 그룹화, 표시를 아이콘 메뉴로 둔다. 공개 링크 화면은 표 보기만 있다.
- 보기 종류, 캔버스 그룹화와 표시, 열 너비와 행 높이는 사람마다 따로 기억한다. 공동 편집 중에도 다른 사람의 화면을 바꾸지 않는다.
- XLSX는 저장된 테스트 세트 전체 케이스를 현재 열 이름과 순서로 내보낸다. QA 진행과 개발 작업상황은 2단 머리글로, 병합 표시 대상 열은 실제 병합 셀로 내보내 현업 시트와 같은 모양을 만든다. 선택 형식 열은 값 목록을 데이터 유효성(드롭다운)으로 함께 내보내 시트에서도 같은 값 중에서 고르게 한다. 목록은 숨긴 시트에 두고, 목록에 없는 기존 값은 그대로 내보낸다. 선택 열의 항목 색은 값별 조건부 서식(셀 배경과 글자색)으로 내보내 시트에서 값을 바꾸면 색도 따라 바뀐다. 회색은 색을 넣지 않는다. 태그 열은 Excel에 여러 값 고르기가 없어 쉼표로 이은 글자로만 내보내고 색을 넣지 않는다. 이미지 셀은 값을 비우고 이미지를 그 셀 안에 맞춰(셀에 고정, 높이 최대 96px) 넣으며 행 높이를 늘린다. GIF와 WebP는 PNG로 바꾸고 움직이는 이미지는 첫 장면을 쓴다. 확인 필요 항목은 포함하지 않는다. 최근 양식은 같은 프로젝트에서 내가 볼 수 있는 가장 최근 수정 세트를 기준으로 하며 없으면 프로젝트 기본 양식을 쓴다. XLSX 묶음 머리글은 해당 두 열이 이웃할 때만 성립하고, 세로 병합은 화면과 같이 글자가 같은 값만 묶고 빈 값은 병합하지 않는다.
- QA 기록 열(QA 결과, QA 담당자, 결과 및 의견, 개발 진행 상태, 개발 담당자, 추가 정보)은 개발자와 기획자, 디자이너가 공개 링크로 들어와 표 안에서 직접 고친다. 댓글, 변경 표시, 처리 흐름 같은 표 밖의 협업 기능은 두지 않는다(2026-10-21 결정). 선택 항목 색은 XLSX에도 조건부 서식으로 내보낸다(2026-10-22 결정, 이전의 화면 전용 결정을 바꿈).

## AI 생성

자세한 설계는 [AI 생성 설계](https://claude.ai/artifact/TsZSVkvJA3KYV3AMGm7KNa)에 있다.

- 입력: Figma 프레임이나 섹션, 테스트 세트 메모(선택), 켜진 열과 작성 기준(사전 정의 열은 작성 지침의 열 규칙, 사용자 열은 사용자가 정한 작성 기준), 기능 그룹, 점검 관점, 화면 구조, 같은 프로젝트 최근 테스트 세트 일부(작성 스타일 예시).
- Figma 원본 JSON은 AI에 보내지 않는다. 플러그인이 보드별 화면 문서와 글자를 읽을 수 있는 크기의 이미지를 만든다. 화면 문서는 반복 항목의 서로 다른 값, 긴 설명과 줄바꿈, 취소선, 노드 ID·부모·위치, 인스턴스 이름과 상태, 연결과 주석을 보존한다. 크기를 줄이려고 내용을 생략하지 않으며 문서와 이미지를 합친 전체 업로드 상한은 200MB다.
- 진행 화면은 단계만 보여준다: 화면 살펴보기, 사용 흐름 이해하기, 테스트 케이스 작성하기, 마무리하기. 케이스 목록, 모델 이름, 개수 같은 내부 정보는 보여주지 않는다.
- 생성 결과의 중복은 같은 기능 그룹 안에서 AI 작성 셀 값이 모두 같은 경우에만 합친다. 기존 케이스와 새 초안에 같은 기준을 적용하며, 다른 그룹의 동일한 테스트는 보존한다. 그룹이 없는 케이스는 미분류끼리 비교한다.
- 끝나면 바로 테스트 세트를 열고 완료를 토스트로 알린다. 사람이 결과를 검토한다는 전제다.
- 점검 관점(내부 고정): 화면 진입과 노출, 정상 흐름 완료, 문구 확인, 입력과 버튼 활성, 실패 응답별 안내, 팝업과 바텀시트의 버튼별 결과, 사용자 상태별(회원 여부, 인증 여부, 앱 설치 여부, 지원 단말), 설정값 조합과 한도(품절, 수량 초과), 이동과 값 유지, 관리자 목록과 조회(조회 조건, 목록 열, 상세, 엑셀 열), 관리자 일괄 처리(1건, 여러 건, 선택 없음, 정상·실패·부분 실패), 관리자 설정의 사용자 화면 반영, 사용자 동작의 관리자 화면 반영(사용자가 만든 주문·등록·신청을 관리자 화면에서 조회·처리, 관리자 화면 이름이 없어도 메모로 판단하도록 항상 대상). 해당 요소가 없으면 건너뛴다. 사용자가 끄거나 더하지 않는다.
- 케이스 나누기: 현업 QA 시트(9/16·9/18·9/30)를 환경 > 테스트 케이스 > 제목 > 행 트리로 재구성해 정한 기준이다(2026-10-23 결정). 테스트 케이스는 시나리오 이름, 제목은 하위 시나리오 이름이다. 같은 묶음의 행은 위쪽 열 값을 그대로 반복해 표에서 병합으로 보인다(2026-10-22 결정).
  - 나누는 단위는 이 순서로 정한다: 같은 지점에서 수행자가 고르는 버튼은 행, 행동 순서가 같고 조건에 따라 결과만 다르면 하위 시나리오(Case), 진입 화면·준비·이어지는 행동 순서가 달라지면 시나리오. 앞 단계에 해당하면 뒤 단계로 나누지 않는다. 단, 정상 흐름이 갈리는 지점 뒤로 더 이어지면 정상 흐름과 그 지점의 비정상 조건 묶음을 서로 다른 시나리오로 두고 비정상 조건끼리만 Case로 나눈다.
  - 시나리오(테스트 케이스): 같은 기능의 진입 화면, 절차를 바꾸는 사용자 유형, 결과가 반영되는 다른 화면, 같은 데이터를 다른 쪽(사용자와 관리자)에서 확인할 때 나눈다. 여정 단계(진입, 탐색, 완료, 종료)는 화면이 바뀌고 단계마다 분기가 따로 있을 때만 나눈다. 테스트 데이터를 먼저 만들어야 하면 그 준비를 첫 시나리오로 둔다. 순서는 진입과 노출, 입력과 활성화, 정상 완료, 취소, 비정상, 반영 화면, 관리자 확인이다.
  - 하위 시나리오(제목): 사용자 상태, 데이터 상태, 입력 값, 설정값에 따라 결과가 달라지면 "Case N. 조건"으로 나눈다(미리 준비할 수 있는 데이터로 갈리는 실패도 포함). 결과 종류는 같고 설정 조합에 따라 세부 결과가 다르면 결과를 먼저 Case N으로 두고 조합마다 "3-1."처럼 하위 번호의 하위 시나리오를 둔다. 결과가 세부까지 같은 조건만 합치고, 상태가 달라도 동작이 같으면 나누지 않는다. 고른 항목 수에 따라 처리가 다르면 1건, 여러 건, 선택 없음으로 나눈다. 조건은 화면과 메모에 정의된 분기와 한도에서 고르고, 명시된 한도에서 결과를 정할 수 있는 경계값은 넣되 새 한도나 오류 정책은 만들지 않는다.
  - 세분화 정도: 지급, 수량, 취소, 권한처럼 로직이 있는 기능은 위 기준을 모두 적용하고, 문구나 디자인만 확인하는 기능은 상태를 한 행의 예상 결과에 모은다.
  - 행은 수행자의 행동 하나와 그 결과다. 흐름의 다음 행동(수행 절차 번호를 이어 쓴다), 같은 지점에서 수행자가 고르는 버튼, 메뉴나 대상만 바꾼 반복은 행을 나눈다. 등록·수정 폼은 입력 항목마다 확인할 결과(검증, 활성, 노출 변화)가 있을 때만 항목마다 한 행이다.
  - 한 행에 둔다: 같은 입력과 데이터로도 서버 상태에 따라 갈리는 응답(정상 처리, 실패, 부분 실패는 예상 결과 안에 나열하고, 응답 뒤 다음 행동이 달라지면 그 행동부터 새 행), 한 행동 뒤 같은 화면에서 함께 보이는 것(예상 결과 불릿), 결과를 확인하지 않는 이동(수행 절차 번호 목록), iOS와 AOS 차이(결과 및 의견에서 나눈다).
  - 사용자/관리자 열은 수행 주체만 쓰고 회원 여부·인증 여부 같은 상태는 하위 시나리오의 조건으로 쓴다.
- 테스트 환경이 여럿(APP, WEB, ADMIN)이고 환경마다 동작이나 분기가 다르면 시나리오 묶음을 환경별로 통째로 반복하고, 그 환경에 없는 분기는 빼고 다른 점만 고친다. 문구 확인처럼 한 번 보고 끝나는 확인은 같은 제목 안에서 환경만 다른 행으로 둔다.
- 확인 필요는 느슨하게 쓴다. 화면이나 설명끼리 달라 예상 결과를 정할 수 없거나, 핵심 규칙이 어디에도 없어 예상 결과를 쓸 수 없을 때만 보낸다.
- 확인 필요는 테스트 세트 오른쪽에서 열리는 전체 높이 drawer에서 처리한다. 상단 항목 이동과 하단 처리 버튼은 고정하고 본문만 스크롤한다. Esc 또는 닫기 버튼으로 닫는다. 수정, 추가, 제외와 복원, 질문에 답하고 다시 작성을 지원한다. 다시 작성은 프레임 없이 그 항목에 남긴 화면 설명, 질문과 답변, 양식, 비슷한 케이스로 AI를 다시 호출한다.
- 케이스 추가 생성은 같은 단계를 쓰고, 기존 케이스를 넣어 중복을 피한다. 새 프레임 없이 메모만으로도 실행한다.
- 모델은 서버가 단계별로 고른다. 기본값은 화면 분석·흐름 분석·케이스 생성·확인 필요 항목 다시 작성에 GPT-5.6 Terra, 최종 정리에 GPT-6 Luna다. 사용자는 AI 제공자를 고르지 않는다.
- 새 테스트 세트에서 처음 생성은 플러그인으로 올린 프레임이 있어야 시작한다. 프레임 없이 만들면 직접 작성으로 열고, 설명만으로는 케이스 추가 생성을 쓴다.
- 생성이 진행 중인 테스트 세트는 진행 중 배너를 보여주고 케이스 추가 생성을 막는다. 같은 테스트 세트에서 생성은 한 번에 하나다.
- 최초 생성, 추가 생성과 다시 작성은 서버 전체 동시 한도(기본 2개)를 공유하며, 한도가 차면 잠시 후 다시 시도하도록 안내한다.
- 생성에 실패하면 이유를 보여주고 테스트 세트로 돌아가게 한다. 올린 프레임은 지워지므로 같은 입력으로 다시 시도하지 않고 설명으로 케이스 추가 생성을 실행한다.

## 임시 업로드

- 플러그인은 프로젝트를 골라 프레임을 올리고, 그 프로젝트를 고른 채 웹의 새 테스트 세트를 연다. 업로드 이름은 없다. 웹에서 프로젝트를 다시 바꿀 수 있다.
- 플러그인의 프로젝트는 필수다. 테스트 세트를 만들 수 있는 프로젝트만 보이고, 지난번 고른 프로젝트를 기본값으로 둔다. 기억한 프로젝트를 고를 수 없으면 비워 두고, 고를 수 있는 프로젝트가 하나면 그것을 고른다.
- 업로드는 임시다. 생성이 끝나면 바로 지우고, 테스트 세트에 쓰지 않으면 1시간 뒤 지운다. 이 정책은 UI에 표시하지 않는다.
- 업로드 자료 목록 화면은 없다.
- 업로드는 사용자를 막지 않는다(2026-10-22 결정). 누른 순간의 선택을 그대로 쓰고, 프레임이 아닌 레이어와 빈 Section은 빼고 프레임만 올린다. 프레임마다 읽는 순간의 모습을 올리며, 업로드 중 다른 곳을 편집해도 멈추지 않는다. 읽는 사이 그 프레임이 바뀌면 조용히 다시 읽는다. 큰 이미지는 줄여서 다시 그리고, 큰 화면 문서는 구조를 덜어내 줄인다. 업로드 중 지워졌거나 끝내 읽지 못한 프레임은 빼고 나머지를 올리며, 완료 화면에 뺀 개수만 보인다. 멈추는 경우는 올릴 프레임이 하나도 없을 때, 로그인이 끝났을 때, 서버에 연결하지 못할 때뿐이다. Figma와 연결이 끊기면 그때까지 읽은 프레임만 올린다.

## 실시간 공동 편집

- 편집 권한이 있는 여러 사람이 스프레드시트처럼 동시에 고친다. 같은 셀은 나중에 온 값이 이긴다.
- 접속자 아바타와 다른 사람이 선택한 셀을 그 사람 색과 이름표로 표시한다. 링크 방문자는 점선 아바타와 "방문자" 표시를 붙인다.
- 미리보기와 변경 충돌 화면은 없다.

## 공유

- 로그인한 계정은 모든 테스트 세트를 보고 편집한다. 사람을 초대하는 기능은 없다.
- 외부 협력사처럼 계정이 없는 사람은 공개 링크로 참여한다. 공개 링크는 꺼짐(기본) 또는 켜짐이고, 켜짐은 보기 가능 또는 편집 가능이다. 링크 새로 만들기로 이전 링크를 바로 무효화한다. 링크 만료일은 없다.
- 링크를 끄거나 새로 만들면 해당 방문자의 열린 화면을 바로 닫는다. 다시 켜면 새 링크가 생긴다.
- 로그인하지 않은 방문자는 "동작 + 동물" 자동 이름(예: 춤추는 수달)을 받는다. 같은 브라우저로 다시 오면 같은 이름이고, 같은 테스트 세트 접속자끼리 겹치지 않는다.
- 로그인한 계정이 공개 링크를 열면 계정 이름과 계정 권한으로 참여한다.
- 로그인하지 않은 방문자는 편집 링크여도 셀 편집과 케이스 추가, 삭제만 한다. 열 추가와 삭제와 순서 변경, 이름 변경, 삭제, AI 생성, 확인 필요 처리, 공유 변경은 계정만 한다. XLSX 내보내기는 방문자도 한다.
- 링크가 꺼진 테스트 세트를 로그인하지 않고 열면 로그인 화면으로 간다.

## 계정

초기 단계에 맞춰 2026-10-22에 간소화했다. 역할, 권한 범위, 소속, 만료일, 초대 링크, 사람별 공유는 필요해질 때 다시 들인다.

- 회원가입은 없다. 관리자가 이름, 아이디, 등급, 처음 비밀번호를 정해 계정을 만들고 직접 전달한다. 메일 발송은 없다.
- 아이디는 로그인 ID다. 영문·숫자·`._-@` 3~64자이며 이메일이 아니어도 된다. 비밀번호는 12자 이상이다.
- 등급은 관리자와 구성원 두 가지다. 구성원은 모든 프로젝트와 테스트 세트를 보고 편집하고, 프로젝트와 테스트 세트를 만들고, 프로젝트 설정을 바꾸고, 플러그인으로 업로드하고, XLSX로 내보내고, 공개 링크를 설정한다. 관리자는 여기에 계정 관리를 더한다.
- 테스트 세트 삭제는 만든 사람과 관리자만 한다.
- 계정 상태는 활성과 비활성이다. 계정은 지우지 않고 비활성화한다. 비활성화하면 바로 로그아웃되고 공동 편집에서 빠지며, 지난 편집 기록의 이름은 남는다. 다시 활성화할 수 있다.
- 비밀번호를 잊으면 관리자가 새 비밀번호를 정해 준다. 그 계정의 로그인은 모두 끊긴다. 본인은 계정 메뉴에서 현재 비밀번호를 넣고 비밀번호를 바꾼다.
- 활성 관리자가 한 명은 남아야 한다. 마지막 관리자를 구성원으로 바꾸거나 비활성화할 수 없다.
- 첫 관리자 계정은 서버 설치 때 CLI로 만든다. CLI가 임시 비밀번호를 출력하고, 로그인 후 바꾼다.

## 플러그인 연결

플러그인에서 로그인을 누르면 브라우저가 열린다. 웹에서 로그인하고 연결을 누르면 플러그인이 계정 토큰을 받고 계정 이름을 표시한다. 머리글의 계정 메뉴에서 웹을 열거나 로그아웃한다. 로그아웃하면 그 플러그인 연결의 토큰을 폐기한다.

고를 수 있는 프로젝트가 없으면 업로드 화면에 배너로 알리고 업로드 버튼을 막는다. 서버에 연결하지 못하면 다시 시도 화면을 보여준다.

## 화면 흐름

- 상단 바: 테스트 세트, 프로젝트, 오른쪽 계정 메뉴(관리 진입, 비밀번호 바꾸기, 로그아웃). 관리 진입은 관리자에게만 보인다.
- 테스트 세트 목록 → 새 테스트 세트(이름, 프로젝트, 양식, Figma 프레임, 메모) → 생성 진행 → 테스트 세트.
- 테스트 세트 화면은 표가 주인공이다. 제목 줄: 제목, 저장 상태, 접속자, 공유, 테스트 세트 작업 메뉴. 그 아래 테두리 있는 도구 상자 하나에 보기 전환, 보기별 도구(표는 셀 도구), 케이스 추가 생성, XLSX 내보내기, 고른 행 삭제, 검색, 확인 필요(개수)를 둔다. 열 편집은 표 머리글에서 한다. 공개 링크 화면도 같은 도구 상자에 셀 도구와 검색을 둔다.
- 화면 안 위치는 상단 바와 제목으로 보여주고 브레드크럼은 쓰지 않는다. 저장 상태는 제목 줄 오른쪽에 둔다.
- 목록의 추가는 머리글 오른쪽 버튼이 기본이고 목록 끝 `+` 행은 보조다. 행 편집과 삭제는 행의 메뉴, 셀 단위 삭제는 호버 ×, 이름 변경은 두 번 클릭 제자리 편집이다.
- 설명 문장, 도움말, 툴팁은 두지 않는다. 설명이 필요하면 구조를 바꾼다.
- 관리: 계정 목록과 만들기, 등급 변경, 비활성화, 비밀번호 다시 정하기.
- 오류 메시지는 짧게 쓰고 토스트로 보여준다.

## 갱신 기준

사용자가 결정한 내용만 반영한다. 제안과 미해결 질문은 `미정·후속 결정` 표에 둔다. 기존 결정을 바꾸면 바뀐 내용과 이유를 함께 갱신한다.

## 로컬 시연 준비

시연 준비자는 저장소를 내려받고 전달받은 API 설정 파일을 배치한 뒤 Docker Compose로 실행한다. 별도의 관리자 초대나 모델 설정 변경 없이 시연 계정으로 로그인할 수 있다. Figma 개발 플러그인 등록과 브라우저 연결 승인은 처음 한 번 직접 진행한다. 시연 범위는 Figma 업로드부터 실제 AI 생성, 케이스 편집과 저장, XLSX 내보내기까지다. 재실행 시 시연 데이터와 계정을 유지한다.
