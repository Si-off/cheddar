# 제품 정의

이 문서는 합의된 제품 목적, 사용자 작업, 지원 범위와 제약을 설명한다. 시안이나 작업 보고만으로 제품 계약을 바꾸지 않는다. 현재 구현은 코드로 확인하고 계약과 다르면 그 차이를 명시한다.

2026-10-18 전면 개편으로 이 문서를 새로 썼고, 2026-10-19에 코드가 이 문서를 따르도록 개편을 마쳤다. 2026-10-21에 시트 개선안(양식 고정과 열 선택, 화면 ID 규칙, 표 편집)을 확정해 이 문서에 반영했다. 이 개선안은 아직 코드에 반영하지 않았으며, 구현 범위는 [프로젝트 구조](architecture.md)의 "시트 개선안" 절에 있다.

## 기능 명칭

- **프로젝트**: 테스트 세트를 만들 때 쓰는 설정 묶음. 양식, 기능 그룹, 화면 구조(화면 ID 규칙 포함), 메모를 가진다.
- **테스트 세트**: 배포마다 만드는 QA 테스트 케이스 묶음. 코드 이름은 `test-set`이다. 표와 카드는 테스트 세트를 보는 방식(보기)이며 이름에 넣지 않는다.
- **테스트 케이스**(줄여서 케이스): 테스트 세트 안의 한 행. 사람이 수행하는 QA 확인 하나.
- **확인 필요**: AI가 생성 중 예상 결과를 하나로 정할 수 없어 사람의 답이 필요한 항목.
- **기능 그룹**: 케이스를 나누는 작은 도메인 단위(예: 주문 조회, 주문 취소).
- **양식**: 테스트 세트의 열 구성. 열은 사전 정의 열과 사용자 열로 나뉜다.
- **사전 정의 열**: 제품이 현업 QA 시트를 분석해 이름, 형식, 작성 기준을 미리 정한 열. 사용자는 켜고 끄기만 한다.
- **사용자 열**: 사용자가 이름, 형식, 작성 기준을 직접 정하는 열.
- **작성 기준**: 열마다 붙는 작성 규칙. AI가 그 열을 채울 때 따른다.
- **화면 ID 규칙**: 화면 ID를 어떤 부분으로 조합하는지 정한 규칙(예: `PC_CPN_REG_PG_001`). 프로젝트마다 여러 개 둘 수 있다.
- **점검 관점**: 생성할 때 빠지면 안 되는 QA 확인의 종류. 제품 내부 로직이며 화면에 노출하지 않는다.
- **보기**: 같은 케이스를 보여주는 방식. 표 보기와 카드 보기가 있다.
- **묶기**: 보기 안에서 케이스를 항목 값으로 묶는 기준.

단위 테스트와 통합 테스트라는 분류와 개념은 쓰지 않는다. 화면, 데이터, 생성 어디에도 이 구분을 두지 않는다.

## 제품 목적과 범위

Cheddar는 사람이 수행하는 QA 테스트 케이스를 Figma 기획 자료로부터 AI로 만들고, 여러 사람이 함께 편집하고, 공유하고, XLSX로 내보내는 사내 도구다. 외부 협력사 개발자도 초대받아 보거나 편집한다.

사용자는 Figma 섹션을 통째로 올리고 메모를 짧게 쓰거나 아예 쓰지 않는다고 가정한다. 그래도 그대로 QA에 쓸 수 있는 테스트 세트가 나와야 한다.

## 구성요소별 역할

| 구성요소 | 역할 |
| --- | --- |
| Figma 플러그인 | 계정 연결과 로그아웃, 프로젝트 고르기, 선택한 프레임과 섹션을 화면 문서와 이미지로 줄여 임시 업로드, 웹의 새 테스트 세트 열기 |

| 백엔드 서버 | 계정과 권한, 프로젝트와 테스트 세트 저장, 임시 업로드, AI 생성 작업 실행, 공동 편집 중계, 공유 링크, XLSX |

## 프로젝트

- 프로젝트는 설정 묶음이다. 테스트 세트를 프로젝트별로 묶어 보여주지 않는다.
- 프로젝트 목록에는 그 프로젝트에 적용되는 권한이 하나라도 있는 프로젝트가 보인다. 전체 범위 권한이 있으면 모든 프로젝트가 보인다. 설정을 바꾸려면 그 프로젝트의 "프로젝트 설정 관리" 권한이 필요하고, 없으면 설정을 보기만 한다. 만들기는 "프로젝트 만들기"(전체만) 권한이다.
- 만들 때 이름(필수)과 설명을 쓴다. 사전 정의 열 14개가 켜진 상태로 함께 만들어진다.
- 사전 정의 열은 현업 QA 시트의 열 순서를 따른다: 테스트 ID, 테스트 환경, 테스트 케이스, 제목, 사용자/관리자, 화면 ID 또는 URL, 수행 절차, 예상 결과, QA 결과, QA 담당자, 결과 및 의견, 개발 진행 상태, 개발 담당자, 추가 정보. 원본의 Case ID는 테스트 ID, Task는 제목, Test Case는 테스트 케이스에 대응한다. 릴리즈 범위와 개별 시나리오 내용은 열에 넣지 않는다.
- 사전 정의 열은 두 묶음이다. AI 작성 열(테스트 ID부터 예상 결과까지)은 Figma 자료에서 채우고, QA 기록 열(QA 결과부터 추가 정보까지)은 비워서 만들고 사람이 채운다. 추가 정보는 기본으로 꺼져 있다.
- 사용자/관리자는 사용자와 관리자 중 선택한다. QA 결과는 Pass, Fail, Deferred, N/A, -, 추가 요청을, 개발 진행 상태는 완료, 수정중, 수정 완료, 보류, 기타, -를 선택값으로 쓴다. 나머지는 텍스트다.
- 사전 정의 열의 작성 기준은 시트 분석으로 정한 작성 규칙이다. 예: 테스트 환경은 APP, WEB, ADMIN처럼 쓰고 같은 값이 이어지면 첫 행에만 쓴다. 테스트 케이스는 화면과 기능을 쓰고 경우가 나뉘면 `Case 1. 정상 등록`처럼 번호를 붙인다. 수행 절차는 번호 목록이고 버튼은 `[등록하기]`로 감싸며 같은 테스트 케이스 안에서 번호를 이어 쓴다. 예상 결과는 `- `로 시작해 `~되는지 확인`으로 끝내고 문구와 버튼은 `문구 : `, `버튼 : ` 뒤에 원문 그대로 적는다. 화면 ID는 화면 구조에 있는 ID만 쓰고 없으면 "추후 채번"으로 둔다. QA 기록 열은 생성 시 비운다.
- 프로젝트 설정 탭: 양식, 기능 그룹, 화면 구조, 메모.
- 양식: 새 테스트 세트의 기본 열을 정한다. 사전 정의 열은 이름, 형식, 작성 기준을 바꿀 수 없고 켜고 끄기만 한다. 테스트 ID와 제목은 항상 켜져 있다. 사용자 열은 이름, 형식(텍스트, 선택, 체크박스, 태그), 작성 기준을 직접 정해 추가하고 편집하고 삭제한다. 선택과 태그의 값 목록은 미리 정하며 AI는 그 목록에서만 고른다. 작성 기준은 AI가 그 열을 채울 때 따르는 설명이며, 자료에 근거가 없으면 비워 두게 한다.
- 기능 그룹: 추가, 이름 변경, 설명 편집, 순서 변경, 삭제. AI는 이 목록에 맞춰 케이스를 나누고 맞는 그룹이 없을 때만 새 그룹을 제안한다.
- 화면 구조: 화면 ID, 이름, 유형(페이지, 팝업, 바텀시트, 탭), 상위 화면, 설명. 화면 ID는 프로젝트 안에서 유일하다. 모듈별로 묶어 보여준다. 기획자의 IA 엑셀(module, Depth, Type, Screen ID 열)을 가져와 채울 수 있다. ID가 없는 행은 건너뛰고 같은 ID가 여러 행이면 첫 행만 가져온다.
- 화면 ID 규칙: 화면 구조 탭 안에서 다룬다. 프로젝트에 규칙을 여러 개 둘 수 있다(예: 관리자 화면 `PC_CPN_REG_PG_001`, 앱 화면 `U_SP_0103_ES_PG_010`). 규칙은 예시 ID를 부분으로 나눈 것이며, 부분마다 이름과 종류(코드 목록, 고정값, 번호)를 정한다. 코드 목록은 코드와 뜻의 쌍이고, 번호는 자릿수를 정하며 앞 부분이 같은 화면끼리 이어서 센다. 부분은 추가, 이름 변경, 종류 변경, 삭제, 끌어서 순서 변경을 한다.
- 규칙이 있으면 화면을 추가할 때 다음 ID를 제안하고, 규칙에 맞지 않는 ID에 "규칙 불일치"를 표시한다. 규칙을 지워도 화면 ID는 그대로 남는다. 규칙 삭제는 확인 대화상자를 거친다. AI는 규칙으로 ID를 지어내지 않는다.
- 메모: 프로젝트마다 하나인 자유 글. 입력을 멈추면 저장한다. AI에 전달하지 않는다.
- 점검 관점은 설정 화면에 없다. 프로젝트 규칙, 화면 분석, 유사 케이스 비교도 없다.

## 테스트 세트와 케이스

- 테스트 세트는 최상위 목록에만 보인다. 목록 필터는 전체, 내 테스트 세트, 공유받은 테스트 세트이고 소유자와 공개 여부를 표시한다.
- 만들 때 이름과 프로젝트를 고르고, 프로젝트는 이후 바꾸지 않는다. 프로젝트 범위 권한이 이 값으로 계산되기 때문이다.
- 새 테스트 세트: 이름, 프로젝트, 양식, Figma 프레임을 정한다. 양식은 프로젝트 기본 양식, 최근 테스트 세트와 같게, 직접 고르기 중 하나다. 앞의 둘은 열 이름을 미리 보여준다. 직접 고르기는 모달에서 표 머리글 모양으로 열을 켜고 끄고 끌어서 순서를 바꾸며 사용자 열을 더한다. 프레임은 플러그인이 올린 것이 모두 선택된 상태에서 눌러 해제한다.
- 새 테스트 세트에서 "직접 작성"을 고르면 케이스 없이 만들고 바로 연다. 생성으로 만드는 흐름은 AI 생성 절을 따른다.
- 볼 수 있는 사람: 소유자, 초대받은 사람, 그 프로젝트에 "모든 테스트 세트 열람" 권한이 있는 사람(보기만). 편집은 소유자와 편집 권한으로 초대받은 사람, 삭제는 소유자만 한다. 내보내기는 그 프로젝트의 "XLSX 내보내기" 권한이 있어야 한다.
- 새 테스트 세트는 고른 양식의 사본을 쓴다. 이후 프로젝트 양식이 바뀌어도 영향을 받지 않는다. 테스트 세트 안에서 열을 더하고 빼고 순서를 바꿀 수 있다.
- 케이스와 프레임, 요구사항, 화면 구조의 연결(근거)은 저장하지 않는다.
- 표 보기: 행과 열 편집, 복사와 붙여넣기, 키보드 이동, 표 안의 세로선과 가로선과 교차점을 끌어 크기 조절. 셀을 고른 뒤 Enter, 두 번 누르기, 글자 입력으로 고치고 Delete로 비운다. 붙여넣기는 탭으로 나뉜 글자를 고른 셀부터 채우며 형식에 맞지 않는 값은 건너뛴다. 묶기 기준을 고르면 묶음별 구역으로 나눈다.
- 셀 편집은 같은 셀이면 나중 값이 이긴다. 저장에 실패하면 알리고 서버의 내용으로 되돌린다.
- 열 추가: 머리글 끝의 `+`에서 양식에서 뺀 사전 정의 열을 되돌리거나 사용자 열을 직접 정의한다. 직접 정의할 때 "기존 케이스 AI로 채우기"를 켜면 기존 케이스를 대상으로 그 열만 AI가 작성한다. 기본은 꺼짐이다.
- 열 머리글 메뉴: 이름 변경, 작성 기준 편집, 왼쪽·오른쪽에 열 추가, 열 삭제. 사전 정의 열은 이름 변경과 작성 기준 편집을 할 수 없다. 열을 지우면 그 열의 값이 함께 지워지므로 확인 대화상자를 거친다.
- 열 순서: 머리글을 끌어서 바꾼다. 테스트 ID는 맨 앞에 고정이고, 묶인 머리글(QA 진행, 개발 작업상황)은 묶음째 움직인다. 열 순서는 테스트 세트 전체에 저장하며 XLSX도 이 순서를 따른다. 바꾼 뒤 되돌리기 토스트를 보여준다.
- 병합 표시: 테스트 환경, 테스트 케이스, 제목, 화면 ID, 수행 절차에서 연속한 같은 값은 병합된 셀로 그린다. 하위 열의 병합은 상위 열의 경계를 넘지 않고, 테스트 ID와 예상 결과는 병합하지 않는다. 값은 모든 행에 저장하므로 필터, 묶기, 확인 필요는 영향을 받지 않는다. 병합된 셀을 고치면 묶음 전체에 반영되고, "셀 나누기"는 병합만 풀어 값을 그대로 남긴다.
- 카드 보기: 묶기 기준의 값마다 열을 만들고 케이스를 카드로 놓는다. 카드를 다른 열로 끌면 그 항목 값이 바뀐다.
- 보기 종류, 묶기 기준, 열 너비와 행 높이는 사람마다 따로 기억한다. 공동 편집 중에도 다른 사람의 화면을 바꾸지 않는다.
- XLSX는 저장된 테스트 세트 전체 케이스를 현재 열 이름과 순서로 내보낸다. QA 진행과 개발 작업상황은 2단 머리글로, 병합 표시 대상 열은 실제 병합 셀로 내보내 현업 시트와 같은 모양을 만든다. 확인 필요 항목은 포함하지 않는다. API의 양식 선택·열 추가/삭제/순서 변경과 XLSX 병합은 2026-10-21 2단계에서 구현했다. 최근 양식은 같은 프로젝트에서 내가 볼 수 있는 가장 최근 수정 세트를 기준으로 하며 없으면 프로젝트 기본 양식을 쓴다. XLSX 묶음 머리글은 해당 두 열이 이웃할 때만 성립하고, 세로 병합은 공백 제거 후 비교하되 빈 값은 병합하지 않는다.

## AI 생성

자세한 설계는 [AI 생성 설계](https://claude.ai/artifact/TsZSVkvJA3KYV3AMGm7KNa)에 있다.

- 입력: Figma 프레임이나 섹션, 테스트 세트 메모(선택), 켜진 열과 작성 기준(사전 정의 열과 사용자 열), 기능 그룹, 점검 관점, 화면 구조, 같은 프로젝트 최근 테스트 세트 일부(작성 스타일 예시).
- Figma 원본 JSON은 AI에 보내지 않는다. 플러그인이 보드별 화면 문서(글자, 인스턴스 이름과 상태, 연결선, 설명 번호 연결, 반복 접기)와 글자를 읽을 수 있는 크기의 이미지로 줄인다.
- 진행 화면은 단계만 보여준다: 화면 살펴보기, 사용 흐름 이해하기, 테스트 케이스 작성하기, 마무리하기. 케이스 목록, 모델 이름, 개수 같은 내부 정보는 보여주지 않는다.
- 끝나면 바로 테스트 세트를 열고 완료를 토스트로 알린다. 사람이 결과를 검토한다는 전제다.
- 점검 관점(내부 고정): 화면 진입과 노출, 정상 흐름 완료, 문구 확인, 입력과 버튼 활성, 실패 응답별 안내, 팝업과 바텀시트의 버튼별 결과, 사용자 상태별(회원 여부, 인증 여부, 앱 설치 여부, 지원 단말), 설정값 조합과 한도(품절, 수량 초과), 이동과 값 유지, 관리자 목록과 조회(조회 조건, 목록 열, 상세, 엑셀 열), 관리자 일괄 처리(1건, 여러 건, 선택 없음, 정상·실패·부분 실패), 관리자 설정의 사용자 화면 반영. 해당 요소가 없으면 건너뛴다. 사용자가 끄거나 더하지 않는다.
- 행 나누기: 수행자의 행동, 입력값, 사전 조건이 달라지면 새 행으로 나눈다. 같은 행동 뒤에 같은 화면에서 여러 가지를 볼 때는 한 셀에 불릿으로 묶는다. 같은 절차에서 결과만 갈리면 행을 나누고 수행 절차는 같은 값으로 둔다.
- 테스트 환경이 여럿(APP, WEB, ADMIN)이면 같은 시나리오를 환경마다 따로 쓴다. iOS와 AOS는 한 행에 두고 결과 및 의견에서 나눈다.
- 확인 필요는 느슨하게 쓴다. 화면이나 설명끼리 달라 예상 결과를 정할 수 없거나, 핵심 규칙이 어디에도 없어 예상 결과를 쓸 수 없을 때만 보낸다.
- 확인 필요는 테스트 세트 오른쪽에서 열리는 전체 높이 drawer에서 처리한다. 상단 항목 이동과 하단 처리 버튼은 고정하고 본문만 스크롤한다. Esc 또는 닫기 버튼으로 닫는다. 수정, 추가, 제외와 복원, 질문에 답하고 다시 작성을 지원한다. 다시 작성은 프레임 없이 그 항목에 남긴 화면 설명, 질문과 답변, 양식, 비슷한 케이스로 AI를 다시 호출한다.
- 케이스 추가 생성은 같은 단계를 쓰고, 기존 케이스를 넣어 중복을 피한다. 새 프레임 없이 메모만으로도 실행한다.
- 모델은 서버가 단계별로 고른다. 기본값은 화면 분석·흐름 분석·케이스 생성·확인 필요 항목 다시 작성에 GPT-5.6 Terra, 최종 정리에 GPT-6 Luna다. 사용자는 AI 제공자를 고르지 않는다.
- 새 테스트 세트에서 처음 생성은 플러그인으로 올린 프레임이 있어야 시작한다. 프레임 없이 만들면 직접 작성으로 열고, 설명만으로는 케이스 추가 생성을 쓴다.
- 생성이 진행 중인 테스트 세트는 진행 중 배너를 보여주고 케이스 추가 생성을 막는다. 같은 테스트 세트에서 생성은 한 번에 하나다.
- 최초 생성, 추가 생성과 다시 작성은 서버 전체 동시 한도(기본 2개)를 공유하며, 한도가 차면 잠시 후 다시 시도하도록 안내한다.
- 생성에 실패하면 이유를 보여주고 테스트 세트로 돌아가게 한다. 올린 프레임은 지워지므로 같은 입력으로 다시 시도하지 않고 설명으로 케이스 추가 생성을 실행한다.

## 임시 업로드

- 플러그인은 프로젝트를 골라 프레임을 올리고, 그 프로젝트를 고른 채 웹의 새 테스트 세트를 연다. 업로드 이름은 없다. 웹에서 프로젝트를 다시 바꿀 수 있다.
- 플러그인의 프로젝트는 필수다. 테스트 세트를 만들 수 있는 프로젝트만 보이고, 지난번 고른 프로젝트를 기본값으로 둔다. 기억한 프로젝트를 고를 수 없으면 비워 두고, 고를 수 있는 프로젝트가 하나면 그것을 고른다.
- 업로드는 임시다. 생성이 끝나면 바로 지우고, 테스트 세트에 쓰지 않으면 1시간 뒤 지운다. 이 정책은 UI에 표시하지 않는다.
- 업로드 자료 목록 화면은 없다.

## 실시간 공동 편집

- 편집 권한이 있는 여러 사람이 스프레드시트처럼 동시에 고친다. 같은 셀은 나중에 온 값이 이긴다.
- 접속자 아바타와 다른 사람이 선택한 셀을 그 사람 색과 이름표로 표시한다. 링크 방문자는 점선 아바타와 "방문자" 표시를 붙인다.
- 미리보기와 변경 충돌 화면은 없다.

## 공유

자세한 기획은 [계정과 공유 기획](https://claude.ai/artifact/1SiN7ymaPgfwiYxZhJxPxv)에 있다.

- 공개 범위: 비공개(소유자, 초대한 계정, 그 프로젝트에 모든 테스트 세트 열람 권한이 있는 계정) 또는 공개(링크가 있는 누구나 로그인 없이).
- 공개 링크 권한: 보기 가능 또는 편집 가능. 링크 새로 만들기로 이전 링크를 바로 무효화한다. 링크 만료일은 없다.
- 사람 초대: 계정을 찾아 편집 가능 또는 보기 가능을 준다. 이름 옆에 소속을 표시한다.
- 새 테스트 세트의 기본 공개 범위는 비공개다.
- 로그인하지 않은 방문자는 "동작 + 동물" 자동 이름(예: 춤추는 수달)을 받는다. 같은 브라우저로 다시 오면 같은 이름이고, 같은 테스트 세트 접속자끼리 겹치지 않는다.
- 로그인한 계정이 공개 링크를 열면 계정 이름으로 참여하고, 초대 권한과 링크 권한 중 높은 쪽을 받는다.
- 비공개로 바꾸거나 링크를 새로 만들거나 초대를 지우면 해당 사람의 열린 화면을 바로 닫는다.
- 권한이 없는 사람이 비공개 링크를 열면 로그인 화면 또는 "접근 권한 없음" 화면과 소유자 이름을 보여준다. 권한 요청 기능은 없다.
- 사람 초대는 그 테스트 세트를 편집할 수 있고 "사람 초대" 권한이 있을 때, 공개 범위와 링크 권한 변경, 링크 새로 만들기는 편집할 수 있고 "공개 링크 만들기" 권한이 있을 때 한다. 초대한 사람의 처음 권한은 편집 가능이다.
- 비공개로 바꾸면 링크와 방문자 이름이 사라지고, 다시 공개하면 새 링크가 생긴다.
- 로그인하지 않은 방문자는 편집 링크여도 셀 편집과 케이스 추가, 삭제만 한다. 열 추가와 삭제와 순서 변경, 이름 변경, 삭제, AI 생성, 확인 필요 처리, 공유 변경은 계정만 한다.

## 계정, 역할, 소속

- 회원가입은 없다. 관리자가 계정을 만들고 초대 링크(7일 유효, 다시 발급 가능)를 직접 전달한다. 받은 사람이 비밀번호를 정한다. 비밀번호 재설정 링크도 관리자가 발급한다. 메일 발송은 없다.
- 계정 상태: 초대됨, 활성, 만료, 비활성. 계정은 지우지 않고 비활성화한다. 비활성화하면 바로 로그아웃되고 공동 편집에서 빠지며, 지난 편집 기록의 이름은 남는다.
- 만료는 만료일이 지난 활성 계정이다. 초대됨·만료·비활성 계정은 로그인할 수 없다. 비밀번호를 다시 설정해도 만료·비활성 상태를 해제하지 않는다.
- 계정 정보: 이름, 이메일(로그인 ID), 소속, 역할 할당 목록, 만료일.
- 역할은 관리자가 만드는 권한 묶음이다. 계정에 여러 역할을 할당하고, 할당마다 범위를 전체 또는 프로젝트(여러 개)로 정한다. 권한은 합친다. 금지 권한은 없다.
- 권한: 테스트 세트 만들기, 사람 초대, 공개 링크 만들기, XLSX 내보내기, 모든 테스트 세트 열람, 프로젝트 설정 관리, 프로젝트 만들기(전체만), 플러그인 업로드(전체만), 계정 관리(전체만), 역할과 소속 관리(전체만). "전체만" 권한은 프로젝트 범위 할당에서 적용되지 않는다.
- 기본 역할: 관리자(모든 테스트 세트 열람을 뺀 모든 권한), 구성원, 외부 참여자(XLSX 내보내기만). 모두 이름과 권한을 바꿀 수 있다.
- 고정 역할 "링크 방문자": 공개 링크 방문자에게 적용한다. XLSX 내보내기만 고를 수 있고 기본값은 허용이다. 계정에 할당하거나 지울 수 없다.
- 역할 설정에 "만료일 필수"와 기본 기간을 둔다. 할당된 역할 중 하나라도 필수면 계정 만료일이 필수이고, 기본 기간은 그중 가장 짧은 값이다. 외부 참여자 기본은 90일이다.
- 역할이 없는 계정도 만들 수 있으며 초대받은 테스트 세트를 받은 권한대로 보고 편집만 한다.
- 소속은 관리자가 이름을 만들고 고치는 표시용 이름표다. 권한과 무관하다.
- "역할과 소속 관리" 권한을 전체 범위로 가진 활성 계정이 한 명은 남아야 한다. 마지막 한 명에게서 이 권한이 빠지는 변경은 막는다.
- 관리자는 비활성 계정이 소유한 테스트 세트의 소유자를 다른 계정으로 넘긴다.
- 첫 관리자 계정은 서버 설치 때 CLI로 만든다.

## 플러그인 연결

플러그인에서 로그인을 누르면 브라우저가 열린다. 웹에서 로그인하고 연결을 누르면 플러그인이 계정 토큰을 받고 계정 이름을 표시한다. 머리글의 계정 메뉴에서 웹을 열거나 로그아웃한다. 로그아웃하면 그 플러그인 연결의 토큰을 폐기한다.

플러그인 업로드 권한이 없거나 고를 수 있는 프로젝트가 없으면 업로드 화면에 배너로 알리고 업로드 버튼을 막는다. 서버에 연결하지 못하면 다시 시도 화면을 보여준다.

## 화면 흐름

- 상단 바: 테스트 세트, 프로젝트, 오른쪽 계정 메뉴(관리 진입, 로그아웃). 관리 진입은 관리 권한이 있을 때만 보인다.
- 테스트 세트 목록 → 새 테스트 세트(이름, 프로젝트, 양식, Figma 프레임, 메모) → 생성 진행 → 테스트 세트.
- 테스트 세트 화면은 표가 주인공이다. 머리글: 접속자, 공유, XLSX 내보내기, 케이스 추가 생성. 도구 줄: 표와 카드 보기 전환, 검색, 묶기 기준, 확인 필요(개수). 열 편집은 표 머리글에서 한다.
- 화면 안 위치는 상단 바와 제목으로 보여주고 브레드크럼은 쓰지 않는다. 저장 상태는 제목 줄 오른쪽에 둔다.
- 목록의 추가는 머리글 오른쪽 버튼이 기본이고 목록 끝 `+` 행은 보조다. 행 편집과 삭제는 행의 메뉴, 셀 단위 삭제는 호버 ×, 이름 변경은 두 번 클릭 제자리 편집이다.
- 설명 문장, 도움말, 툴팁은 두지 않는다. 설명이 필요하면 구조를 바꾼다.
- 관리: 계정, 역할, 소속 탭.
- 오류 메시지는 짧게 쓰고 토스트로 보여준다.

| 성능 목표의 수치 | 미정 |

## 갱신 기준

사용자가 결정한 내용만 반영한다. 제안과 미해결 질문은 `미정·후속 결정` 표에 둔다. 기존 결정을 바꾸면 바뀐 내용과 이유를 함께 갱신한다.

## 로컬 시연 준비

시연 준비자는 저장소를 내려받고 전달받은 API 설정 파일을 배치한 뒤 Docker Compose로 실행한다. 별도의 관리자 초대나 모델 설정 변경 없이 시연 계정으로 로그인할 수 있다. Figma 개발 플러그인 등록과 브라우저 연결 승인은 처음 한 번 직접 진행한다. 시연 범위는 Figma 업로드부터 실제 AI 생성, 케이스 편집과 저장, XLSX 내보내기까지다. 재실행 시 시연 데이터와 계정을 유지한다.
