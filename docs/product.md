# 제품 정의

이 문서는 현재 합의된 제품의 기준이다. 개별 작업의 계획이나 아이디어를 확정된 제품 요구사항으로 취급하지 않는다.

## 제품 목적과 범위

Cheddar는 사람이 수행하는 QA 테스트 케이스를 AI로 생성하고, 편집·공유·XLSX 내보내기 할 수 있는 제품이다.

- 단위 테스트 케이스: 개별 화면·기능을 대상으로 사람이 수행하는 QA 케이스.
- 통합 테스트 케이스: 여러 화면에 걸친 사용자 흐름을 대상으로 사람이 수행하는 QA 케이스.

이 구분은 제품 안에서 작성하는 QA 케이스의 범위를 뜻한다. 프로젝트 코드의 단위·통합 테스트 도구 선택을 의미하지 않는다.

## 구성요소별 역할

| 구성요소 | 확정된 역할 |
| --- | --- |
| Figma 플러그인 | 선택한 Figma 프레임의 데이터·이미지 업로드에 집중 |
| 웹 | AI 테스트 케이스 생성·편집, 공유와 XLSX 내보내기 제공 |
| 백엔드 서버 | 프로젝트·파일·업로드·시트·IA·기본 양식 저장과 XLSX 제공. AI 실행은 후속 단계 |

## 편집과 공유

- 편집 UI는 엑셀 같은 표 중심으로 구성하며 긴 내용은 상세 패널에서 수정한다.
- 팀·개인별 작성 방식에 대응하는 구성 자유도와 인터랙션을 지향한다. 열 추가, 열 이름 정의, 열 순서 변경, 열 너비 조절, 일반 문자열 검색 기능을 포함한다.
- 사용자 정의 열은 텍스트부터 지원한다. 검색은 표시 문자열 전체의 대소문자 구분 없는 부분 일치다. 후보는 별도 목록이다.
- 공유는 후속 단계의 링크 열람 기능이며, 도입 시 초기 링크는 읽기 전용이다.
- 링크별 편집 권한 지원은 향후 범위다.

## 초기 검증 환경

- 로그인과 검색 노출 없이 개발자 PC에서 로컬 검증한다.
- 백엔드와 DB도 로컬에서 실행한다.
- 사내 배포는 추후 결정한다. 로컬 링크 열람의 구체적인 접근 범위와 연결 방식은 미정이다.

## 승인된 업무 모델과 단계 경계

2026-10-15 [1단계 설계안](changes/2026-10-15-stage-1-foundation/design.md)을 승인했다. 아래는 제품 계약이며, 현재 구현 범위와 구분한다. 이미지 시안은 구현 요구사항으로 사용하지 않는다.

- 프로젝트는 기본 양식·IA·업로드 묶음·시트를 묶는다. 프로젝트 이름은 1~100자이며 중복을 허용한다.
- 플러그인은 프로젝트를 선택하고 프레임 데이터·이미지를 하나의 업로드 묶음으로 등록한다. 초기 업로드 교체·버전 관리는 제외한다.
- 새 시트는 프로젝트 기본 양식의 사본을 사용한다. 기존 시트는 기본 양식 변경의 영향을 받지 않는다. 업로드 없이 빈 시트도 만들 수 있다.
- 케이스는 생성 전부터 편집 가능하다. 기본 필드는 케이스 번호·제목·사전조건·수행 단계·기대 결과·우선순위·프레임 연결·IA 화면 연결이며, 내부 UUID와 표시용 케이스 번호는 별개다.
- 수행 단계와 기대 결과는 긴 문자열이다. 우선순위는 높음·보통·낮음 또는 미지정이다. 빈 초안 저장을 허용한다.
- 시스템 열은 이름·순서·너비를 변경하고 사용자 정의 열은 추가·수정·삭제한다. 시스템 열 삭제는 초기 제외한다. 사용자 열 삭제 시 해당 값도 제거한다.
- 자동 저장은 미저장 입력을 보존하며 수정 충돌을 덮어쓰지 않는다. 실제 화면의 복붙·키보드·상세 패널은 2B에서 구현·검증한다.
- IA 화면 ID는 프로젝트 내에서 유일하고 대소문자를 구분한다. Figma node ID와 별개다. 내부 UUID로 연결하므로 화면 ID 이름이 바뀌어도 연결을 유지한다. 참조 중인 항목은 연결 해제 후 삭제한다.
- IA는 수작업 및 XLSX·CSV 분석 결과 검토·수정·확정으로 등록한다. AI가 화면 연결을 확신하지 못하면 비워둘 수 있으며 그 이유만으로 후보로 보내지 않는다.
- 플로우차트는 시트별이며 의미·IA 연결과 위치·확대율을 분리한다. 시작·종료·화면·행동·조건 분기와 방향·조건 연결을 지원한다. 이미지/Figma 프레임 분석 결과는 검토 후 사용한다. 플로우 없이도 통합 생성할 수 있다.
- AI는 실행마다 Claude/OpenAI를 선택한다. 프레임·IA·선택 설명·플로우·시트 양식·기존 예시를 입력으로 사용하며 사용자가 목표 개수를 정하지 않는다. 새 시트 생성 또는 기존 시트 교체만 지원한다.
- 근거가 명확한 결과는 케이스, 추론·모호한 결과는 이유를 포함한 후보로 분리한다. 후보의 검토 대기·추가됨·제외됨을 저장하고 제외 항목 다시 보기를 지원한다.
- 생성 중 대상 시트만 잠근다. 결과가 정상 준비된 뒤 교체하고 실패 시 기존 내용을 보존한다. LangGraph 사용은 확정했으나 내부 그래프·재시도·복구는 3B에서 논의한다.
- XLSX는 저장된 현재 시트 전체 케이스를 현재 열 이름·순서로 내보낸다. 검색 필터와 후보는 포함하지 않는다.
- 초기 기준 규모는 업로드 묶음 약 20프레임, 시트 약 500케이스다. 검증된 성능이나 생성 목표·개수 제한을 뜻하지 않는다.

현재 API는 프로젝트·파일·업로드 묶음·시트·IA·기본 양식·XLSX를 제공한다. 프로젝트 설정의 이름·설명, 수작업 IA 계층 관리, 기본 양식 편집은 웹에 연결됐고 실제 DB·브라우저 검증을 마쳤다. 시트 편집·업로드 연계 화면은 연결 후 최종 검증 중이다. 실제 Figma 업로드 검증과 AI 생성·IA 파일 분석·공유는 남아 있다.

## 갱신 기준

사용자가 결정한 내용을 반영하고, 관련 작업이나 결정 기록이 있으면 연결한다. 제안과 미해결 질문은 확정 항목에 섞지 않는다. 기존 결정을 바꾸면 현재 내용과 결정 근거를 함께 갱신한다.
